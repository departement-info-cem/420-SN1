# ⚙️ Création de fonctions

<Tabs className="tabs-collants" queryString="onglet">

    <TabItem value="intro" label="Fonction" default>

        :::info Rappel sur les fonctions
        - Une fonction est un bloc de code réutilisable qui effectue une tâche spécifique.
        - Nous avons déjà **utilisé** des fonctions existantes, comme `print()`, `max()` ou `round()`. Dans cette rencontre, nous allons **créer** les nôtres.
        - Une fonction peut prendre des **paramètres** (des valeurs d'entrée) et retourner une **valeur de sortie**.
        - Les fonctions permettent de **structurer le code**, de **réduire la répétition** et de **faciliter la maintenance** du code.
        :::

        ---

        :::info Fonction simple

        Voici une fonction très simple :

        ```python showLineNumbers
        def double(x):
            return 2 * x
        ```

        - **Première ligne** : `def double(x):`
            - `def` est un mot-clé qui indique que nous sommes en train de définir une fonction.
            - `double` est le nom que nous avons décidé de donner à notre fonction.
                - 💡 **Bien nommer une fonction :** utilisez un **verbe** qui décrit ce qu'elle fait, écrit en `snake_case` (minuscules et `_`), par exemple `calculer_moyenne` ou `afficher_rapport`.
            - Les parenthèses `()` indiquent que c'est une fonction, et peuvent contenir des paramètres (ici un seul : `x`).
            - `x` est un paramètre que nous avons décidé de nommer `x` et qui prend la valeur transmise lors de l'appel de la fonction.
            - Le `:` à la fin de la ligne indique que le corps (le code) de la fonction commence à la ligne suivante.
        - **Toutes les lignes suivantes** (ici seulement une ligne : `return 2 * x`)
            - Elles forment le **corps** de la fonction : elles sont **indentées** (décalées vers la droite) avec la touche **`TAB`**.
                - ⚠️ **En Python, c'est l'indentation qui indique quelles lignes font partie de la fonction.** Voir l'explication détaillée plus bas.
            - `return` est un mot-clé qui indique quelle valeur la fonction renvoie, ici le résultat de l'évaluation de l'expression `2 * x`.

        👉 **Définir une fonction, ce n'est pas l'exécuter.** \
        Quand Python lit ces deux lignes, il ne calcule rien : il **retient** simplement que la fonction `double` existe et ce qu'elle doit faire. \
        C'est comme écrire une recette de cuisine : la recette est prête, mais le plat n'est pas encore préparé. \
        Le code de la fonction ne sera exécuté que lorsque nous l'**appellerons**, ce que nous verrons juste après.

        :::

        ---

        ::::info Appel d'une fonction

        Une fois qu'une fonction est ainsi définie, on peut *l'appeler*, en lui transmettant une valeur pour `x` :

        ```python showLineNumbers
        def double(x):
            return 2 * x

        double(5)  # Appel de la fonction en lui passant la valeur 5
        ```

        :::tip-nt

        Pour appeler une fonction, on écrit son nom suivi de parenthèses contenant les valeurs à transmettre aux paramètres. \
        Lorsqu'une fonction est appelée, le code à l'intérieur de la fonction est exécuté, et la valeur spécifiée par `return` est renvoyée à l'endroit où la fonction a été appelée.

        :::

        Ici, la fonction `double` est appelée en lui passant la valeur `5`, ce qui signifie que `x` reçoit la valeur `5` à l'intérieur de la fonction. \
        La fonction calcule `2 * 5` et retourne `10`.

        Cependant, ici, la valeur retournée par la fonction est **perdue** : la fonction fonctionne, mais le résultat disparaît si on ne le stocke pas. \
        Il est plus utile de stocker cette valeur dans une variable. Remplaçons la ligne 4 par :

        ```python showLineNumbers=4
        resultat = double(5)  # Appel de la fonction et stockage de la valeur retournée dans la variable 'resultat'
        print(resultat)       # Affiche 10
        ```

        👉 Une fonction qui fait un `return` **renvoie** une valeur, elle ne l'**affiche** pas. Pour la voir, il faut l'afficher avec `print()`. \
        Si vous confondez `print()` et `return`, lisez l'aide-mémoire [return vs print](/aidememoire/return-print).

        ::::

        ---

        :::note-nt

        Une fois une fonction définie, elle peut être appelée autant de fois que souhaité dans le code, en utilisant son nom suivi de parenthèses et des valeurs nécessaires :

        ```python
        resultat1 = double(5)  # Appel de la fonction avec la valeur 5
        resultat2 = double(10) # Appel de la fonction avec la valeur 10
        resultat3 = double(2)  # Appel de la fonction avec la valeur 2

        print(resultat1)       # Affiche 10
        print(resultat2)       # Affiche 20
        print(resultat3)       # Affiche 4
        ```
        :::

        ---

        :::tip-nt

        Pour passer des valeurs à une fonction, il est aussi possible d'utiliser des variables :

        ```python
        a = 5
        resultat = double(a)  # Appel de la fonction en lui passant la valeur contenue dans la variable 'a'
        print(resultat)       # Affiche 10
        ```

        Ici, la variable `a` contient la valeur `5`, et lorsque nous appelons `double(a)`, la fonction reçoit la valeur de `a` (c'est-à-dire `5`) et retourne `10`.

        👉 La variable s'appelle `a` et le paramètre s'appelle `x` : ce n'est pas un problème! C'est la **valeur** qui est transmise, pas le nom de la variable.

        :::

        ---

        :::danger Deux erreurs fréquentes lors de l'appel
        **Erreur 1 : appeler la fonction avant de la définir**
        ```python showLineNumbers
        resultat = double(5)
        def double(x):
            return 2 * x
        ```
        Dans la console, Python affiche ce message d'erreur :

        <Traceback>

        ```
        Traceback (most recent call last):
          File "...\r03_fonction.py", line 1, in <module>
            resultat = double(5)
                       ^^^^^^
        NameError: name 'double' is not defined
        ```

        </Traceback>

        🔎 Lisez d'abord la **dernière ligne** : elle donne le **type** d'erreur (`NameError`) et sa cause. La ligne `line 1` indique **où** chercher. \
        Python lit le code de haut en bas : à la ligne 1, il ne connaît pas encore `double`. \
        👉 Écrivez toujours vos fonctions **en haut** du fichier, avant le code qui les appelle.

        **Erreur 2 : oublier les parenthèses**
        ```python showLineNumbers
        def double(x):
            return 2 * x

        print(double)  # Affiche <function double at 0x000001D540C71440>
        ```
        Sans parenthèses, la fonction **n'est pas appelée** : Python affiche la fonction elle-même (son adresse en mémoire), et non son résultat. \
        👉 Pour l'appeler, il faut les parenthèses et la valeur : `print(double(5))`.
        :::

        ---

        ::::info 📏 L'indentation : un élément essentiel en Python

        En Python, l'**indentation** est le décalage vers la droite que l'on met au début d'une ligne. \
        Ce décalage n'est **pas décoratif** : il indique à Python **quelles lignes forment un bloc de code**. \
        L'indentation peut changer complètement le sens d'un programme!

        **Un bloc de code, c'est par exemple :**
        - 🔧 le **corps d'une fonction** (ce que nous voyons dans cette rencontre)
        - 🔀 le contenu d'une **structure conditionnelle** (plus tard dans le cours)
        - 🔁 le contenu d'une **boucle** (plus tard dans le cours)

        **Comment ça fonctionne :**

        1. Une ligne qui se termine par `:` annonce qu'un **bloc** va suivre (ex : `def double(x):`).
        2. Les lignes du bloc sont **décalées vers la droite** par rapport à cette ligne.
        3. Le bloc se termine à la première ligne qui **revient au niveau** de la ligne qui contient le `:`.

        ```python showLineNumbers
        def double(x):
            y = 2 * x  # Indentée : fait partie de la fonction
            return y   # Indentée : fait partie de la fonction
        z = 3          # Non indentée : le bloc est terminé, cette ligne est hors de la fonction
        ```

        - Les lignes 2 et 3 sont **indentées** : elles forment le corps de la fonction `double`.
        - La ligne 4 **revient au niveau** de la ligne `def` : elle est en dehors de la fonction.

        :::tip-nt
        **Règle d'or :** toutes les lignes d'un même bloc doivent avoir **exactement la même indentation**.
        :::
        ::::

        ---

        :::info ⌨️ Comment indenter : utilisez la touche TAB
        - ✅ **`TAB`** : ajoute une indentation (décale la ligne vers la droite).
        - ✅ **`Maj + TAB`** : retire une indentation (décale la ligne vers la gauche).
        - ❌ **Ne jamais utiliser la barre d'espace pour indenter!**

        Si vous sélectionnez plusieurs lignes, `TAB` et `Maj + TAB` les décalent toutes en même temps.

        **Pourquoi ✅ `TAB` et jamais la ❌ barre d'espace?**
        - `TAB` crée toujours le même décalage : l'indentation est **uniforme**.
        - Avec la barre d'espace, il est très facile d'oublier un espace ou d'en ajouter un de trop, et l'erreur est presque invisible à l'œil.
        - Un seul espace de trop suffit pour provoquer une `IndentationError`.

        👉 Voir aussi la section sur la tabulation de l'aide-mémoire [**⌨️ Symboles au clavier**](/aidememoire/clavier#tabulation).
        :::

        ---

        :::danger IndentationError : une erreur fréquente chez les débutants
        Une indentation incorrecte empêche le programme de s'exécuter. Python affiche alors une erreur `IndentationError`. \
        Dans PyCharm, la ligne fautive est généralement soulignée en rouge avant même l'exécution, et l'erreur s'affiche dans la console si on lance le programme.

        **Cas 1 : on oublie d'indenter le corps de la fonction**
        ```python showLineNumbers
        def double(x):
        return 2 * x  # IndentationError: expected an indented block after function definition on line 1
        ```
        **Cas 2 : une ligne est plus indentée que les autres du même bloc**
        ```python showLineNumbers
        def double(x):
            y = 2 * x
             return y  # IndentationError: unexpected indent
        ```
        **Pour corriger :** donnez la même indentation à toutes les lignes du bloc, en utilisant `TAB`.
        ```python showLineNumbers
        def double(x):
            y = 2 * x
            return y
        ```
        :::

        ---

        :::tip Une fonction vide : `pass`
        Une fonction doit contenir **au moins une instruction** indentée. Mais parfois, on veut déclarer une fonction qu'on écrira **plus tard**, par exemple pour construire un programme étape par étape.

        On utilise alors `pass` : une instruction qui ne fait **rien**, mais qui sert d'espace réservé.
        ```python showLineNumbers
        def calculer_moyenne(notes):
            pass                        # À écrire plus tard

        print("Le reste du programme fonctionne déjà!")
        ```
        Sans `pass`, Python afficherait une erreur : `IndentationError: expected an indented block after function definition on line 1`.

        👉 N'oubliez pas de remplacer le `pass` par le vrai code de la fonction une fois prêt!
        :::

        ::::info Paramètres

        Les paramètres sont les valeurs d'**entrée** d'une fonction.

        Les fonctions peuvent prendre un nombre variable de paramètres, y compris aucun paramètre du tout. \
        Voici 3 fonctions avec différents nombres de paramètres :

        ```python showLineNumbers
        def nombre_pi():
            return 3.14159

        def carre(x):
            return x * x

        def puissance(base, exposant):
            return base ** exposant
        ```

        - `nombre_pi` est une fonction sans paramètre qui retourne la valeur de π.
        - `carre` est une fonction avec un seul paramètre `x` qui retourne le carré de `x`.
        - `puissance` est une fonction avec deux paramètres, `base` et `exposant`, qui retourne la base élevée à la puissance de l'exposant.

        👉 Les paramètres sont séparés par des virgules. \
        👉 À l'intérieur de la fonction, un paramètre s'utilise comme une variable, qui n'existe **que dans la fonction** (voir l'onglet [Portée](/cours/rencontre3?onglet=portee)).

        Lorsqu'on appelle une fonction, il faut lui passer le même nombre de valeurs que de paramètres définis :

        ```python
        pi = nombre_pi()       # Appel sans argument : les parenthèses restent obligatoires, même vides
        carre_de_5 = carre(5)  # Appel avec un argument : x reçoit 5
        ```

        Lorsque la fonction a plusieurs paramètres, l'ordre des valeurs transmises doit correspondre à l'ordre des paramètres définis dans la fonction :

        ```python
        resultat1 = puissance(2, 3)  # base reçoit 2 et exposant reçoit 3 (retourne 8)
        resultat2 = puissance(3, 2)  # base reçoit 3 et exposant reçoit 2 (retourne 9)
        ```

        :::warning-nt
        ⚠️ Python ne signale **aucune erreur** si vous inversez l'ordre : le programme s'exécute, mais le résultat est **faux**. \
        C'est le pire type de bogue, car on ne le voit pas!
        :::

        ::::

        ---

        :::note Paramètre ou argument?
        Ces deux mots sont souvent confondus :
        - le **paramètre** est le **nom** écrit entre les parenthèses du `def` (ex : `x` dans `def carre(x):`);
        - l'**argument** est la **valeur** donnée lors de l'appel (ex : `5` dans `carre(5)`).

        Les messages d'erreur de Python utilisent le mot *argument* : c'est utile de le reconnaître!
        :::

        ---

        :::danger TypeError : le mauvais nombre d'arguments
        Si on ne donne pas autant d'arguments qu'il y a de paramètres, Python affiche une erreur `TypeError`.

        **Il manque un argument :**
        ```python showLineNumbers
        def puissance(base, exposant):
            return base ** exposant

        resultat = puissance(2)
        ```

        <Traceback>

        ```
        Traceback (most recent call last):
          File "...\r03_parametres.py", line 4, in <module>
            resultat = puissance(2)
        TypeError: puissance() missing 1 required positional argument: 'exposant'
        ```

        </Traceback>

        **Il y a un argument de trop :** avec `resultat = puissance(2, 3, 4)`, la dernière ligne devient :

        <Traceback>

        ```
        TypeError: puissance() takes 2 positional arguments but 3 were given
        ```

        </Traceback>

        👉 La dernière ligne indique **le nom de la fonction** et **ce qui ne va pas** : comparez l'appel avec la ligne `def`.
        :::

        ---

        :::tip Paramètre avec valeur par défaut
        Il est possible de définir une valeur par défaut pour un paramètre. \
        Si aucune valeur n'est fournie pour un paramètre lors de l'appel de la fonction, la valeur par défaut sera utilisée.

        💡 Vous l'avez déjà utilisé à la rencontre 2 : `round(17.8)` arrondit à l'entier, alors que `round(3.14159, 2)` arrondit à 2 décimales. Le 2ᵉ paramètre de `round()` est **facultatif**!

        ```python showLineNumbers
        def puissance(base, exposant=2):
            return base ** exposant

        resultat1 = puissance(5)     # retourne 25, car exposant prend la valeur par défaut 2
        resultat2 = puissance(5, 3)  # retourne 125, car exposant prend la valeur 3 fournie lors de l'appel
        ```

        Comme dans cet exemple, une fonction peut posséder à la fois des paramètres avec des valeurs par défaut et des paramètres sans valeurs par défaut.

        Les **paramètres obligatoires** (ceux qui n'ont pas de valeur par défaut) doivent **toujours** être placés **avant les paramètres facultatifs** (ceux qui ont une valeur par défaut). \
        Sinon, Python affiche une erreur : `SyntaxError: parameter without a default follows parameter with a default`. \
        Cette règle permet à l'utilisateur de la fonction de **fournir les valeurs pour les paramètres essentiels en priorité**, tout en ayant la liberté de **spécifier uniquement les options supplémentaires** s'il le souhaite.

        ```python showLineNumbers
        def prix_total(prix, quantite=1, taxe=1.15):
            return prix * quantite * taxe

        # Exemples d'appels
        total1 = prix_total(10)                 # 10 * 1 * 1.15 = 11.5
        total2 = prix_total(10, 3)              # 10 * 3 * 1.15 = 34.5
        total3 = prix_total(10, 3, 1.2)         # 10 * 3 * 1.2 = 36.0
        total4 = prix_total(10, taxe=1.2)       # 10 * 1 * 1.2 = 12.0
        ```

        La dernière ligne de cet exemple est particulièrement intéressante à analyser :
        - on fournit un prix (`10`) ;
        - on ne fournit aucune valeur pour la quantité, la valeur par défaut sera utilisée (`1`) ;
        - malgré l'absence de valeur pour la quantité, on peut fournir une valeur pour la taxe, en utilisant le nom du paramètre (`taxe=1.2`) : c'est un **argument nommé**.

        Avec des arguments nommés, l'ordre n'a plus d'importance : `puissance(exposant=3, base=2)` retourne `8`.

        :::

        ---

        :::note Une liste comme paramètre

        Un paramètre peut être de n'importe quel type y compris une **liste**. \
        À l'intérieur de la fonction, on accède aux éléments de la liste via leur index, comme on l'a vu à la rencontre précédente.

        Voici une fonction qui reçoit une liste de 3 notes et retourne leur moyenne :

        ```python showLineNumbers
        def calculer_moyenne(notes):
            """
            Calcule la moyenne de 3 notes.

            Paramètre :
            notes (list) : Une liste contenant 3 notes numériques.

            Retourne :
            float : La moyenne des 3 notes.
            """
            return (notes[0] + notes[1] + notes[2]) / 3

        notes_alice = [14, 17, 12]
        notes_bob = [9, 11, 15]

        moyenne_alice = calculer_moyenne(notes_alice)
        moyenne_bob = calculer_moyenne(notes_bob)

        print(f"Moyenne d'Alice : {round(moyenne_alice, 2)}")
        print(f"Moyenne de Bob : {round(moyenne_bob, 2)}")
        ```

        👉 On passe la liste entière en un seul paramètre. À l'intérieur de la fonction, `notes[0]`, `notes[1]` et `notes[2]` donnent accès à chacune des valeurs. Appeler la fonction avec des listes différentes produit des résultats différents sans réécrire la logique.

        :::

    <TabItem value="retour" label="Retour">

        :::info `return`

        La valeur retournée est la **sortie** de la fonction.

        Une fonction peut retourner plusieurs valeurs, séparées par des virgules :

        ```python showLineNumbers
        def diviser(a, b):
            quotient = a // b
            reste = a % b
            return quotient, reste

        q, r = diviser(10, 3)  # q reçoit 3 et r reçoit 1
        ```

        Dans cet exemple, la fonction `diviser` retourne à la fois le quotient entier (`//`) et le reste (`%`) de la division. \
        Ces valeurs sont ensuite assignées à deux variables distinctes (`q` et `r`), séparées par une virgule lors de l'appel de la fonction.

        👉 Il faut autant de variables à gauche du `=` que de valeurs retournées, et dans le **même ordre** : la 1ʳᵉ variable reçoit la 1ʳᵉ valeur, la 2ᵉ reçoit la 2ᵉ.

        :::

        ---

        :::tip Après le `return`, on revient à l'appel
        Quand Python rencontre un `return`, il quitte la fonction et **revient à la ligne qui l'a appelée**, en y apportant la valeur retournée.

        👉 Vous le verrez dans vos traces : dans l'exemple de l'onglet [Trace](/cours/rencontre3?onglet=trace), après chaque appel de `carre`, l'exécution revient à la ligne 7 (`total = carre(a) + carre(b)`).
        :::

        ---

        :::tip-nt

        L'exécution de la fonction s'arrête dès qu'une instruction `return` est rencontrée : le code placé **après** n'est jamais exécuté.

        ```python showLineNumbers
        def double(x):
            return 2 * x
            print("Ce message ne s'affichera jamais!")  # Jamais exécuté
        ```

        PyCharm grise d'ailleurs ce code et affiche l'avertissement *This code is unreachable* (« ce code est inaccessible »). \
        Pour cette raison, l'instruction `return` est généralement placée à la toute fin d'une fonction.

        Cependant, une fonction peut comporter plusieurs instructions `return` à différents endroits du code, notamment dans des conditions différentes. \
        Nous verrons les conditions plus tard, mais voici tout de même un exemple simple :

        ```python showLineNumbers
        def plus_grand(a, b):
            if a > b:
                return a
            else:
                return b
        ```

        :::

        ---

        ::::warning Fonction sans `return`

        Une fonction peut ne pas avoir d'instruction `return`. \
        Dans ce cas, elle retourne automatiquement la valeur `None`.

        Par exemple, la fonction ci-dessous affiche simplement une salutation à la console sur 2 lignes :

        ```python showLineNumbers
        def salutation(nom, age):
            print("Bonjour")
            print(f"Je m'appelle {nom}, j'ai {age} ans")
        ```

        C'est pareil comme si `return None` était ajouté à la fin de la fonction :

        ```python showLineNumbers
        def salutation(nom, age):
            print("Bonjour")
            print(f"Je m'appelle {nom}, j'ai {age} ans")
            return None
        ```

        Par exemple, avec le code ci-dessous :
        ```python showLineNumbers=5
        resultat = salutation("Gustave", 32) # Affiche la salutation, puis stocke `None` dans `resultat`
        print(resultat)                      # Affiche la valeur de `resultat`, qui est `None`
        print(salutation("Sciel", 32))       # Affiche la salutation, puis affiche la valeur de retour `None`
        ```

        La console affiche :
        ```
        Bonjour
        Je m'appelle Gustave, j'ai 32 ans
        None
        Bonjour
        Je m'appelle Sciel, j'ai 32 ans
        None
        ```

        :::danger
        Pour cette raison, n'affichez jamais le résultat d'une fonction qui ne retourne rien! \
        Cela affichera toujours `None`, ce qui n'a aucun sens.
        ```python showLineNumbers
        # bonne utilisation :
        salutation("Gustave", 32)  # Affiche la salutation

        # mauvaise utilisation :
        print(salutation("Gustave", 32))  # Affiche la salutation, puis `None`
        ```
        :::

        ::::

        ---

        ::::info Pourquoi retourner plutôt qu'afficher?

        Une valeur **retournée** peut être **réutilisée** : dans un calcul, dans une variable, dans un autre appel de fonction…

        <Row>
            <Column>
            **✅ Avec `return`**
            ```python showLineNumbers
            def double(x):
                return 2 * x

            resultat = double(5) + 1
            print(resultat)  # Affiche 11
            ```
            </Column>
            <Column>
            **❌ Avec `print`**
            ```python showLineNumbers
            def afficher_double(x):
                print(2 * x)

            resultat = afficher_double(5) + 1
            print(resultat)
            ```
            </Column>
        </Row>

        La version avec `print` affiche `10`, puis plante : la fonction retourne `None`, et on ne peut pas additionner `None` et `1`.

        <Traceback>

        ```
        10
        Traceback (most recent call last):
          File "...\r03_retour.py", line 4, in <module>
            resultat = afficher_double(5) + 1
                       ~~~~~~~~~~~~~~~~~~~^~~
        TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'
        ```

        </Traceback>

        🔎 Lisez la dernière ligne : `NoneType` est le type de `None`. Quand vous voyez `NoneType` dans une erreur, demandez-vous : **« Ai-je oublié un `return`? »**

        ::::

        ---

        :::info-nt

        On peut aussi définir une fonction qui construit et retourne une chaîne de caractères, sans jamais afficher quoi que ce soit à l'écran :

        ```python showLineNumbers
        def salutation(nom, age):
            return f"Bonjour\nJe m'appelle {nom}, j'ai {age} ans."

        # Stocke la chaîne de caractères retournée par la fonction dans la variable 'message'
        message = salutation("Gustave", 32)

        print(message)  # Affiche le message stocké dans la variable 'message'
        ```

        👉 Dans une chaîne, `\n` crée un **saut de ligne** : le message s'affiche donc sur 2 lignes.

        👉 Si jamais vous êtes confus.e entre `print()` et `return`, lisez l'aide-mémoire [return vs print](/aidememoire/return-print).

        :::

    <TabItem value="portee" label="Portée">

        :::info Portée des variables

        La portée d'une variable, c'est la partie du code où elle **existe** et où on peut l'utiliser. \
        En Python, il existe deux types principaux de portée : locale et globale.
        :::

        ---

        :::info Portée globale
        Une variable définie en dehors d'une fonction est globale. \
        **Elle peut être utilisée dans tout le programme**, y compris à l'intérieur des fonctions,
        <u>sauf si une variable du même nom est définie localement</u> (cette situation est montrée plus bas).

        ⚠️ C'est possible, mais **à éviter** : voir la bonne pratique à la fin de cet onglet.


        ```python showLineNumbers
        x = 10  # Variable globale

        def ma_fonction():
            print(f"Valeur de x dans la fonction : {x}")  # x est accessible ici

        ma_fonction()
        print(f"Valeur de x en dehors de la fonction : {x}")
        ```
        :::

        ---

        ::::info Portée locale
        Une variable définie à l'intérieur d'une fonction est locale. **Elle n'existe que dans cette fonction**. \
        Les paramètres d'une fonction **sont** des variables locales : ils reçoivent leur valeur au moment de l'appel.

        ```python showLineNumbers
        def ma_fonction(z):  # z a une portée locale
            y = 5            # y est une variable locale
            print(f"Valeur de y dans la fonction : {y}")
            print(f"Valeur de z dans la fonction : {z}")

        ma_fonction(7)
        ma_fonction(4)

        print(y)  # Erreur : y n'existe pas en dehors de la fonction
        ```

        La ligne 9 provoque une erreur, car `y` n'existe pas à l'extérieur de la fonction :

        <Traceback>

        ```
        Traceback (most recent call last):
          File "...\r03_portee.py", line 9, in <module>
            print(y)
                  ^
        NameError: name 'y' is not defined
        ```

        </Traceback>

        `print(z)` donnerait la même erreur : le paramètre `z` n'existe pas non plus à l'extérieur de la fonction.

        :::tip-nt
        🔁 **Les variables locales sont recréées à chaque appel.** \
        Au 1ᵉʳ appel (ligne 6), `y` et `z` sont créées, puis **disparaissent** à la fin de la fonction. \
        Au 2ᵉ appel (ligne 7), elles sont créées **à nouveau** : la fonction ne se « souvient » pas de l'appel précédent.
        :::

        ::::

        ---

        :::info 🕵️ La portée dans vos traces
        Vous vous demandiez à quoi servent les colonnes *contexte* et *portée* de la feuille de trace? Les voici!
        - Chaque fonction a **son propre groupe de colonnes** de variables : c'est sa **portée**. Les variables globales ont aussi le leur (*globale*).
        - La colonne ***contexte*** indique **où se trouve l'exécution** : `globale`, ou le **nom de la fonction** en cours d'exécution.
        - À la fin d'un appel, les variables locales de la fonction **disparaissent** : leurs colonnes se vident.

        👉 Voyez-le dans l'exemple de l'onglet [Trace](/cours/rencontre3?onglet=trace) : les fonctions `affiche_resultat` et `carre` ont chacune leurs colonnes, et le contexte change à chaque appel.
        :::

        ---

        ::::warning ⚠️ Affecter une valeur dans une fonction crée une variable locale

        Dès qu'une fonction **affecte une valeur** à une variable (avec `=`), cette variable devient **locale** à la fonction, même si une variable globale porte déjà le même nom.

        👉 En pratique : une fonction peut **lire** une variable globale, mais ne peut **pas la modifier**.

        #### Cas 1 : la fonction crée une variable locale du même nom

        ```python showLineNumbers
        x = 10  # Variable globale

        def ma_fonction():
            x = 5  # Nouvelle variable locale : la globale n'est pas touchée
            print(f"Valeur locale de x : {x}")  # Affiche 5

        ma_fonction()
        print(f"Valeur globale de x : {x}")  # Affiche 10
        ```

        Dans la fonction, la variable locale `x` **cache** la variable globale, sans la modifier : après l'appel, la globale vaut toujours `10`. \
        Même nom, mais **2 variables différentes** : dans votre [trace](/recettes/produire-une-trace), **prévoyez 2 colonnes**!

        #### Cas 2 : la fonction tente de modifier la variable globale

        ```python showLineNumbers
        compteur = 0  # Variable globale

        def incrementer():
            compteur = compteur + 1  # ❌ UnboundLocalError

        incrementer()
        ```

        Ce code plante avec l'erreur suivante :

        <Traceback>

        ```
        Traceback (most recent call last):
          File "...\r03_compteur.py", line 6, in <module>
            incrementer()
            ~~~~~~~~~~~^^
          File "...\r03_compteur.py", line 4, in incrementer
            compteur = compteur + 1
                       ^^^^^^^^
        UnboundLocalError: cannot access local variable 'compteur' where it is not associated with a value
        ```

        </Traceback>

        Remarquez les **2 niveaux** : l'erreur survient à la ligne 4, **dans** `incrementer`, qui a été appelée à la ligne 6. Vous verrez pourquoi dans l'onglet [Pile](/cours/rencontre3?onglet=pile).

        **Pourquoi?** À cause du `=` de la ligne 4, `compteur` est une variable **locale** dans toute la fonction. \
        Pour calculer `compteur + 1`, Python cherche donc la valeur de cette variable locale... qui n'en a encore aucune!

        :::tip-nt
        ✅ **La solution :** la fonction reçoit la valeur en **paramètre** et **retourne** le résultat. \
        C'est le programme principal, **à l'extérieur** de la fonction, qui met à jour la variable globale.

        ```python showLineNumbers
        compteur = 0

        def incrementer(valeur):
            return valeur + 1

        compteur = incrementer(compteur)  # La variable globale est modifiée ici, hors de la fonction
        print(compteur)                   # Affiche 1
        ```
        :::

        :::note-nt
        🚫 En cherchant sur le Web ou avec l'IA, vous trouverez peut-être le mot-clé `global` comme « solution ». \
        **Ne l'utilisez pas dans ce cours** : il crée exactement les problèmes décrits ci-dessous. Utilisez plutôt un paramètre et un `return`.
        :::

        ::::

        ---

        ::::danger 🚫 Bonne pratique : évitez les variables globales dans vos fonctions!

        Ce n'est pas parce qu'une fonction **peut** lire une variable globale qu'elle **doit** le faire. \
        Si une fonction a besoin d'une information, on la lui **transmet en paramètre**. \
        👉 **Une fonction devrait utiliser uniquement ses paramètres et ses variables locales.**

        <Row>
            <Column size={6}>

                ❌ **À éviter** : la fonction utilise la variable globale `masse`

                ```python showLineNumbers
                masse = 75

                def calculer_poids(gravite):
                    return masse * gravite  # masse vient de l'extérieur!

                print(calculer_poids(9.81))
                ```

            </Column>
            <Column size={6}>

                ✅ **À privilégier** : la masse est transmise en paramètre

                ```python showLineNumbers
                masse = 75

                def calculer_poids(masse_kg, gravite):
                    return masse_kg * gravite  # uniquement des paramètres

                print(calculer_poids(masse, 9.81))
                ```

            </Column>
        </Row>

        **Pourquoi éviter les variables globales dans une fonction?**
        - 🔍 **Dépendance cachée** : en lisant l'appel `calculer_poids(9.81)`, rien n'indique que la fonction a aussi besoin de `masse`. Il faut lire tout son code pour le découvrir.
        - ♻️ **Fonction moins réutilisable** : copiée dans un autre programme ou importée depuis un module, elle plante (`NameError`) si `masse` n'y existe pas.
        - 🧪 **Plus difficile à tester** : pour calculer le poids d'une autre masse, il faut modifier la variable globale au lieu de simplement passer une autre valeur.
        - 🐞 **Plus difficile à déboguer** : si la variable globale est modifiée ailleurs dans le programme, le résultat de la fonction change sans que son appel ait changé.

        :::tip-nt
        **Règle simple :** limitez au maximum les variables globales. \
        Une fonction bien écrite est comme une boîte noire : tout ce qui entre passe par ses **paramètres**, et tout ce qui sort passe par son **`return`**.
        :::

        ::::

    <TabItem value="DRY" label="DRY">

        :::info Éviter la répétition : créez des fonctions!

        En programmation, on suit souvent le principe **DRY** (*Don't Repeat Yourself*). \
        Si vous remarquez que vous copiez-collez du code en changeant seulement quelques valeurs, il est temps de créer une fonction!

        Prenons un exemple en physique spatiale où l'on calcule et affiche le poids d'un spationaute dont la masse est de 75 kg sur différents astres (rappel : le poids est une force en newtons (N) calculée par la formule $P = m \times g$).

        ```python showLineNumbers
        masse_spationaute = 75

        # Calcul et affichage pour la Terre
        poids_terre = masse_spationaute * 9.81
        print(f"Sur l'astre Terre, le poids est de {poids_terre:.2f} N.")

        # Calcul et affichage pour Mars
        poids_mars = masse_spationaute * 3.71
        print(f"Sur l'astre Mars, le poids est de {poids_mars:.2f} N.")

        # Calcul et affichage pour la Lune
        poids_lune = masse_spationaute * 1.62
        print(f"Sur l'astre Lune, le poids est de {poids_lune:.2f} N.")
        ```

        Ici, les lignes de calcul et d'affichage sont répétées trois fois. C'est l'occasion idéale pour extraire le tout dans des fonctions.
        :::

        ---

        :::note-nt
        Dans cet exemple, on va créer 2 fonctions : une pour faire le calcul du poids, et une pour faire l'affichage, qui appellera la première fonction pour faire le calcul.

        Commençons par la fonction de calcul.
        :::

        ---

        ## Fonction 1 : calcul du poids

        :::note-nt

        ### Étape 1 : Identifier les éléments qui changent

        Regardez attentivement les blocs de code répétés et identifiez ce qui varie d'un bloc à l'autre. Ces variables deviendront les **paramètres** de notre fonction.

        Dans notre exemple, voici ce qui change :
        - La valeur de la gravité (`9.81`, `3.71`, `1.62`)
        - La masse pourrait aussi changer si on veut être plus flexible (`75`).

        Ce qui reste identique, c'est l'opération mathématique (la multiplication) et la phrase affichée dans le `print()`.
        :::

        ---

        ::::note-nt

        ### Étape 2 : Extraire la fonction de calcul (avec retour)

        Commençons par isoler le calcul mathématique.
        On veut créer une fonction qui reçoit les variables nécessaires, effectue le calcul, et nous redonne le résultat.

        - **Paramètres** : la masse (`masse_kg`) et la gravité (`gravite`).
        - **Variable locale** : le résultat du calcul (`poids`). Elle n'existera que pour le temps de ce calcul.
        - **Valeur de retour** : le `poids` calculé (le résultat de la multiplication).

        ```python showLineNumbers
        def calculer_poids(masse_kg, gravite):
            poids = masse_kg * gravite
            return poids
        ```
        👉 Cette fonction est **pure** : son résultat dépend **seulement de ses paramètres**, et elle ne fait rien d'autre (aucun affichage, aucune modification à l'extérieur de la fonction). \
        C'est exactement la « boîte noire » décrite dans l'onglet [Portée](/cours/rencontre3?onglet=portee).
        ::::

        ---

        :::info-nt

        ### Résultat intermédiaire : intégration du calcul

        Nous avons maintenant isolé la logique mathématique. Le programme principal appelle maintenant notre fonction `calculer_poids` au lieu de réécrire la formule à chaque fois.

        ```python showLineNumbers
        def calculer_poids(masse_kg, gravite):
            poids = masse_kg * gravite
            return poids

        masse_spationaute = 75

        # On utilise maintenant la fonction pour obtenir les valeurs
        p_terre = calculer_poids(masse_spationaute, 9.81)
        print(f"Sur l'astre Terre, le poids est de {p_terre:.2f} N.")

        p_mars = calculer_poids(masse_spationaute, 3.71)
        print(f"Sur l'astre Mars, le poids est de {p_mars:.2f} N.")

        p_lune = calculer_poids(masse_spationaute, 1.62)
        print(f"Sur l'astre Lune, le poids est de {p_lune:.2f} N.")
        ```

        👉 **Observation** : Le calcul est maintenant isolé dans une fonction (si la formule change ou contient une erreur, on ne la corrige qu'à un seul endroit). Cependant, on remarque que les instructions `print()` sont encore très répétitives. On va donc extraire une deuxième fonction pour gérer l'affichage, et qui appellera la fonction de calcul pour obtenir le poids.
        :::

        ---

        ## Fonction 2 : affichage du poids

        :::note-nt

        ### Étape 1 : Identifier ce que la fonction doit afficher

        Regardez les lignes d'affichage et identifiez ce qui varie d'une ligne à l'autre.

        Dans notre exemple, la phrase affichée contient :
        - le nom de l'astre (`"Terre"`, `"Mars"`, `"Lune"`)
        - le poids calculé à partir de la masse et de la gravité

        La structure de la phrase reste toujours la même.

        :::

        ---

        :::note-nt

        ### Étape 2 : Extraire la fonction d'affichage (sans retour)

        Nous allons créer une deuxième fonction qui gère le texte affiché, et qui appellera notre première fonction pour obtenir le poids.

        - **Paramètres** : le nom de l'astre (`nom_astre`), la masse (`masse_kg`) et la gravité (`gravite`).
        - **Variable locale** : le poids calculé par l'appel de fonction (`poids_calcule`).
        - **Valeur de retour** : aucune (elle ne fera que des `print()`).

        ```python showLineNumbers
        def afficher_poids_astre(nom_astre, masse_kg, gravite):
            # Appel à l'autre fonction pour faire le calcul
            poids_calcule = calculer_poids(masse_kg, gravite)

            # Affichage du résultat
            print(f"Sur l'astre {nom_astre}, le poids est de {poids_calcule:.2f} N.")
        ```

        👉 **Une fonction peut en appeler une autre!** Ici, `afficher_poids_astre` appelle `calculer_poids`. Pour voir comment Python s'y retrouve, consultez l'onglet [Pile](/cours/rencontre3?onglet=pile).

        🕵️ Remarquez que `masse_kg` et `gravite` existent dans **les deux** fonctions : ce sont **4 variables différentes**, chacune dans la portée de sa fonction. Dans votre trace, elles ont donc chacune leur colonne!
        :::

        ---

        :::info-nt

        ### Résultat final : intégration de l'affichage

        Une fois nos deux fonctions créées, notre programme principal devient beaucoup plus court et plus lisible!

        ```python showLineNumbers
        # --- Définition des fonctions ---

        def calculer_poids(masse_kg, gravite):
            poids = masse_kg * gravite
            return poids

        def afficher_poids_astre(nom_astre, masse_kg, gravite):
            poids_calcule = calculer_poids(masse_kg, gravite)
            print(f"Sur l'astre {nom_astre}, le poids est de {poids_calcule:.2f} N.")

        # --- Programme principal ---

        masse_spationaute = 75

        afficher_poids_astre("Terre", masse_spationaute, 9.81)
        afficher_poids_astre("Mars", masse_spationaute, 3.71)
        afficher_poids_astre("Lune", masse_spationaute, 1.62)
        ```

        La console affiche :
        ```
        Sur l'astre Terre, le poids est de 735.75 N.
        Sur l'astre Mars, le poids est de 278.25 N.
        Sur l'astre Lune, le poids est de 121.50 N.
        ```

        👉 Si demain on veut changer la phrase affichée ou modifier le format d'affichage, on n'aura qu'à modifier **un seul endroit** dans le code au lieu de trois. \
        👉 Et pour ajouter un astre, il suffit maintenant d'**une seule ligne** :
        ```python
        afficher_poids_astre("Jupiter", masse_spationaute, 24.79)  # Sur l'astre Jupiter, le poids est de 1859.25 N.
        ```
        :::

        ---

        :::tip-nt

        ### 📋 Variante avec des listes parallèles

        Les données utilisées pour appeler nos fonctions peuvent être organisées dans des **listes parallèles** : plusieurs listes où **le même index** correspond au même élément. Voici comment réécrire le programme principal en regroupant les noms des astres et leurs gravités dans des listes :

        ```python showLineNumbers
        # --- Définition des fonctions (inchangées) ---

        def calculer_poids(masse_kg, gravite):
            poids = masse_kg * gravite
            return poids

        def afficher_poids_astre(nom_astre, masse_kg, gravite):
            poids_calcule = calculer_poids(masse_kg, gravite)
            print(f"Sur l'astre {nom_astre}, le poids est de {poids_calcule:.2f} N.")

        # --- Programme principal avec des listes parallèles ---

        masse_spationaute = 75
        noms_astres = ["Terre", "Mars", "Lune"]
        gravites = [9.81, 3.71, 1.62]

        afficher_poids_astre(noms_astres[0], masse_spationaute, gravites[0])
        afficher_poids_astre(noms_astres[1], masse_spationaute, gravites[1])
        afficher_poids_astre(noms_astres[2], masse_spationaute, gravites[2])
        ```

        👉 À l'index `0` on trouve tout ce qui concerne la Terre (`noms_astres[0]` et `gravites[0]`), à l'index `1` Mars, et ainsi de suite. Les données restent parfaitement synchronisées.

        💡 Avec les **boucles** que vous verrez bientôt, il sera possible de parcourir ces listes automatiquement peu importe le nombre d'astres dans la liste!

        :::

        ---

        :::tip 🧭 La méthode DRY en 3 questions
        1. **Qu'est-ce qui change** d'une répétition à l'autre? Ce sont les **paramètres**.
        2. **Qu'est-ce qui reste pareil?** C'est le **corps** de la fonction.
        3. **On remplace** chaque répétition par un **appel** de la fonction, avec les bonnes valeurs.
        :::

        :::info Commentaires dans le code

        Il est possible d'ajouter des commentaires dans le code pour expliquer ce que fait une fonction ou pour donner des indications sur son utilisation. \
        Les commentaires sont ignorés par l'interpréteur Python et n'affectent pas l'exécution du code. \
        Ils sont utiles pour rendre le code plus lisible et compréhensible pour les autres développeurs (et pour vous-même dans le futur!).

        En Python, les commentaires sont créés en utilisant le symbole `#` pour commenter **une ligne entière** ou **une partie de ligne** (tout ce qui est à droite du `#`).

        ```python
        # Ceci est un commentaire sur une seule ligne
        total = 0  # Ceci est un commentaire en fin de ligne
        ```

        ⌨️ Dans PyCharm, **`Ctrl + /`** commente (ou décommente) les lignes sélectionnées. C'est très pratique pour désactiver temporairement du code pendant le débogage!
        :::

        ---

        :::tip Un bon commentaire explique le **pourquoi**, pas le **quoi**
        Le code dit déjà **ce qu'il fait**. Un commentaire utile explique **pourquoi** on le fait.
        ```python
        x = x + 1                       # ❌ Ajoute 1 à x (répète le code, inutile)
        tentatives = tentatives + 1     # ✅ Une tentative de plus après chaque erreur
        ```
        :::

        ---

        :::info Docstring : documenter une fonction

        Pour documenter une fonction, il est possible d'utiliser les triples guillemets `"""` (ou `'''`). \
        Ce type de documentation se nomme un ***docstring***. Il se place sur la **première ligne du corps** de la fonction, indenté, juste après la ligne `def`. \
        Placé ailleurs, ce n'est plus un docstring : PyCharm ne l'affichera pas. \
        Créer une fonction sans mettre une documentation est une mauvaise pratique!

        Par exemple :
        ```python showLineNumbers
        # Ceci est un commentaire sur une seule ligne
        def energie_cinetique(masse, vitesse): # Ceci est un commentaire en fin de ligne
            """
            Calcule l'énergie cinétique d'un objet en mouvement.

            Paramètres :
            masse (float) : Masse de l'objet en kilogrammes (kg)
            vitesse (float) : Vitesse de l'objet en mètres par seconde (m/s)

            Retourne :
            float : Énergie cinétique en joules (J)

            Exemple d'utilisation :
            energie_cinetique(10, 5) retourne 125.0
            """
            nb_joules = 0.5 * masse * vitesse ** 2
            return nb_joules

        # Exemple avec différentes valeurs
        objet1 = energie_cinetique(2, 3) # Masse de 2 kg, vitesse de 3 m/s
        objet2 = energie_cinetique(5, 7) # Masse de 5 kg, vitesse de 7 m/s

        # Affichage des résultats
        print(f"Énergie cinétique de l'objet 1 : {objet1} joules")  # 9.0 joules
        print(f"Énergie cinétique de l'objet 2 : {objet2} joules")  # 122.5 joules
        ```

        Les lignes 3 à 15 constituent un ***docstring*** : un bloc utilisant des triples guillemets pour expliquer en détail la fonction `energie_cinetique`. \
        Lorsqu'une fonction possède une documentation sous forme de ***docstring***, l'IDE vous permet de visualiser cette documentation rapidement. \
        Par exemple, si vous placez votre souris sur l'un des deux appels de fonction `energie_cinetique`, la documentation sera affichée.

        <p align="left">
            <img src={require('/img/cours/R03_exemple_docstring_affiché.png').default} alt="Infobulle de PyCharm affichant le docstring de energie_cinetique" style={{ verticalAlign: 'middle' }} width="50%" />
        </p>

        Les docstrings ne servent qu'à la documentation et elles sont ignorées par Python lors de l'exécution du code. \
        Il en est de même pour les lignes 1, 19 et 23, qui sont des commentaires sur une seule ligne, ainsi que tout ce qui se trouve à droite du `#` aux lignes 2, 20, 21, 24 et 25.

        :::

        ---

        :::warning ⚠️ Le gabarit automatique de PyCharm
        Si vous tapez `"""` puis `Entrée` juste sous un `def`, PyCharm génère automatiquement un docstring dans un autre format (`:param masse:`, `:return:`). \
        👉 Dans ce cours, utilisez plutôt le **format montré ci-dessus** (`Paramètres :`, `Retourne :`).
        :::

        ---

        :::info 📝 Votre docstring dans le TP1
        Les docstrings sont évaluées dans le [TP1](/tp/tp1) (1 point). Chaque docstring doit décrire clairement :
        1. le **rôle** de la fonction;
        2. ses **paramètres** (nom, type, signification et unité);
        3. sa **valeur de retour** (type et signification);
        4. les **exceptions** possibles.

        Le tout dans un **français sans faute**!

        👉 Les exceptions seront vues à la [rencontre 4](/cours/rencontre4?onglet=exceptions-validation) : vous ajouterez alors une section `Exceptions :` à vos docstrings.
        :::

        :::info Créer nos propres modules

        À la rencontre 2, nous avons **utilisé** des modules existants comme `math` et `random`. \
        Bonne nouvelle : un module, ce n'est rien d'autre qu'un **fichier `.py`**. Donc **n'importe quel fichier Python que vous écrivez peut devenir un module!**

        👉 Créer un module permet de **regrouper des fonctions** autour d'un même thème et de les **réutiliser dans plusieurs programmes**, sans jamais les copier-coller à la main. \
        C'est le prolongement naturel du principe [DRY](/cours/rencontre3?onglet=DRY) : au lieu de répéter du code dans un même fichier, on évite de le répéter **d'un fichier à l'autre**.

        📖 La [recette sur les modules](/recettes/creer-module) montre pas à pas comment créer un module dans PyCharm. Cet onglet va plus loin : il explique **ce qui se passe réellement** lors d'un `import`.

        :::

        ---

        ::::info Exemple : un module `physique.py`

        Reprenons le calcul du poids vu dans l'onglet [DRY](/cours/rencontre3?onglet=DRY). Plaçons la fonction dans son propre fichier, puis utilisons-la depuis un autre fichier.

        📁 Les deux fichiers doivent être **dans le même dossier**.

        <Row>
            <Column size={6}>

                **Le module** : il contient les fonctions réutilisables.

                ```python title="physique.py" showLineNumbers
                GRAVITE_TERRE = 9.81  # m/s²

                def calculer_poids(masse, gravite):
                    """Retourne le poids (N) d'un objet."""
                    return masse * gravite
                ```

            </Column>
            <Column size={6}>

                **Le programme principal** : il importe le module et l'utilise.

                ```python title="r03_poids.py" showLineNumbers
                import physique

                poids = physique.calculer_poids(75, physique.GRAVITE_TERRE)
                print(f"Poids : {poids} N")
                ```

            </Column>
        </Row>

        - On écrit `import physique`, **sans** l'extension `.py` : le **nom du module** est le nom du fichier sans `.py`.
        - Comme pour `math`, on accède au contenu du module avec la syntaxe `nom_du_module.nom`.
        - Les deux méthodes vues à la rencontre 2 fonctionnent aussi avec nos modules : `from physique import calculer_poids` est tout à fait valide.
        - Grâce au ***docstring***, PyCharm affiche la documentation de `calculer_poids` quand vous placez la souris sur l'appel, **même si la fonction est dans un autre fichier**. C'est une raison de plus de bien [commenter vos fonctions](/cours/rencontre3?onglet=comments)!
        - `GRAVITE_TERRE` est une **constante** : comme vu à la rencontre 1, on l'écrit en **majuscules** pour indiquer que sa valeur ne devrait jamais être modifiée.

        📝 Dans cet onglet, les docstrings sont **abrégés** pour alléger les exemples. Dans vos programmes (et dans le TP1), écrivez-les au complet : rôle, paramètres, valeur de retour et exceptions.

        :::tip-nt
        **Bien nommer son module** : comme pour une variable, utilisez des lettres minuscules et des `_` (ex. : `outils_texte.py`). \
        Pas d'espaces, pas de tirets `-`, pas d'accents et ne commencez pas par un chiffre : `import 1-mon module` n'est pas du Python valide!
        :::

        ::::

        ---

        ::::info 📋 Que fait concrètement un `import`?

        Quand Python rencontre `import physique`, il fait essentiellement ceci :

        1. Il **cherche** le fichier `physique.py` (d'abord dans le dossier du programme, ensuite parmi les modules installés avec Python).
        2. Il **exécute tout le fichier**, de la première à la dernière ligne, exactement comme si vous l'aviez lancé.
        3. Il **rend disponible** tout ce que ce fichier a créé (fonctions, variables) sous le nom `physique`.

        👉 Vous pouvez donc imaginer un `import` comme un **copier/coller automatique** du contenu du module au début de votre programme :

        <Row>
            <Column size={6}>

                **Ce que vous écrivez**

                ```python title="r03_poids.py" showLineNumbers
                import physique

                poids = physique.calculer_poids(75, physique.GRAVITE_TERRE)
                print(f"Poids : {poids} N")
                ```

            </Column>
            <Column size={6}>

                **Ce que Python exécute (à peu près)**

                ```python showLineNumbers
                # ----- début du contenu de physique.py -----
                GRAVITE_TERRE = 9.81  # m/s²

                def calculer_poids(masse, gravite):
                    """Retourne le poids (N) d'un objet."""
                    return masse * gravite
                # ----- fin du contenu de physique.py -----

                poids = calculer_poids(75, GRAVITE_TERRE)
                print(f"Poids : {poids} N")
                ```

            </Column>
        </Row>

        :::note-nt Nuances par rapport au vrai copier/coller
        L'analogie est très utile pour comprendre **ce qui s'exécute**, mais elle n'est pas parfaite :
        - **Le code n'est écrit qu'à un seul endroit.** \
        Si vous corrigez un bogue dans `physique.py`, **tous** les programmes qui l'importent profitent de la correction. \
        Avec un vrai copier/coller, il faudrait corriger chaque copie!
        - **Les noms restent « rangés » dans le module.** \
        Avec `import physique`, on doit écrire `physique.calculer_poids` : cela évite les conflits si votre programme possède déjà une fonction du même nom. \
        Avec `from physique import calculer_poids`, le nom est copié directement dans votre programme : on se rapproche alors du vrai copier/coller.
        - **Un module n'est exécuté qu'une seule fois.** \
        Si le même module est importé deux fois, Python réutilise le résultat du premier `import`.
        :::

        :::tip-nt
        📁 Après votre premier `import`, un dossier `__pycache__` peut apparaître dans votre projet. C'est une version « précompilée » de vos modules que Python garde pour aller plus vite.
        Vous pouvez l'ignorer : il sera recréé automatiquement au besoin.
        :::

        ::::

        ---

        ::::warning ⚠️ Impact des instructions dans la portée globale d'un module

        Puisqu'un `import` **exécute tout le fichier du module**, toutes les instructions placées dans sa **portée globale** (à l'extérieur des fonctions) sont exécutées au moment de l'import. \
        Un `def` ne fait que **définir** une fonction (rien ne s'affiche), mais un `print()`, un `input()` ou un appel de fonction, lui, **s'exécute vraiment**!

        Supposons que vous ayez testé votre fonction directement dans le module :

        <Row>
            <Column size={6}>

                ```python title="physique.py" showLineNumbers {7-8}
                GRAVITE_TERRE = 9.81  # m/s²

                def calculer_poids(masse, gravite):
                    """Retourne le poids (N) d'un objet."""
                    return masse * gravite

                # Tests de la fonction
                print(calculer_poids(10, GRAVITE_TERRE))
                ```

            </Column>
            <Column size={6}>

                ```python title="r03_poids.py" showLineNumbers
                import physique

                poids = physique.calculer_poids(75, physique.GRAVITE_TERRE)
                print(f"Poids : {poids} N")
                ```

            </Column>
        </Row>

        En exécutant `r03_poids.py`, on obtient :

        ```
        98.10000000000001
        Poids : 735.75 N
        ```

        😕 La première ligne ne vient pas de notre programme : c'est le **test** de la ligne 8 de `physique.py`, exécuté pendant l'`import`. \
        (Le `...0001` vient de la [précision des flottants](/cours/rencontre2?onglet=precision-flottants) vue à la rencontre 2 : la fonction est correcte.) \
        Imaginez maintenant que le module contienne un `input()` : votre programme poserait une question inattendue avant même de commencer!

        :::tip-nt
        ✅ **Règle :** la portée globale d'un module devrait contenir uniquement :
        - des `import`;
        - des **constantes** (comme `GRAVITE_TERRE`);
        - des **définitions de fonctions** (`def`).

        Tout le reste (tests, `print()`, `input()`, appels de fonctions) va dans un bloc `if __name__ == "__main__":` (voir ci-dessous).
        :::

        :::note-nt
        🔗 Lien avec l'onglet [Portée](/cours/rencontre3?onglet=portee) : les variables globales d'un module sont accessibles par le programme qui l'importe (ex. : `physique.GRAVITE_TERRE`). C'est pratique pour des **constantes**, mais la bonne pratique tient toujours : une fonction du module **ne devrait pas dépendre de variables globales**. Elle reçoit ce dont elle a besoin **en paramètre**, sinon elle risque de ne plus fonctionner une fois importée ailleurs.
        :::

        ::::

        ---

        ::::info `if __name__ == "__main__":`

        Comment garder nos tests dans le module, **sans** qu'ils s'exécutent lors d'un `import`? \
        Python fournit une variable spéciale, `__name__` (deux `_` de chaque côté), qui existe automatiquement dans **chaque fichier** :

        | Comment le fichier est utilisé                  | Valeur de `__name__` dans ce fichier |
        | ----------------------------------------------- | ------------------------------------ |
        | Exécuté **directement** (bouton ▶ dans PyCharm) | `"__main__"`                         |
        | **Importé** par un autre fichier                | le nom du module, ex. : `"physique"` |

        Il suffit donc de vérifier cette valeur pour savoir si le fichier est « le programme principal » ou s'il est importé :

        :::note-nt
        🔜 Le `if` (une condition) et la comparaison `==` seront vus à la [rencontre 4](/cours/rencontre4). \
        Pour l'instant, retenez cette ligne comme une **formule** : le code **indenté** en dessous s'exécute **seulement** si on lance ce fichier directement.
        :::

        ```python title="physique.py" showLineNumbers {7-10}
        GRAVITE_TERRE = 9.81  # m/s²

        def calculer_poids(masse, gravite):
            """Retourne le poids (N) d'un objet."""
            return masse * gravite

        if __name__ == "__main__":
            # Ce bloc s'exécute seulement si on lance physique.py directement
            print(calculer_poids(10, GRAVITE_TERRE))  # 98.10000000000001
            print(calculer_poids(10, 1.62))           # Sur la Lune : 16.200000000000003
        ```

        | Action                               | Résultat                                                         |
        | ------------------------------------ | ---------------------------------------------------------------- |
        | Exécuter `physique.py`               | Les tests des lignes 9 et 10 s'affichent : on peut tester le module. |
        | Exécuter `r03_poids.py` (qui importe `physique`) | `__name__` vaut `"physique"` : le bloc est ignoré, seul `Poids : 735.75 N` s'affiche. |

        ::::

        ---

        :::danger Erreurs fréquentes

        | Erreur                                                                      | Cause probable                                                                                                              |
        | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
        | `ModuleNotFoundError: No module named 'physique'`                           | Le module n'est pas dans le même dossier que le programme, ou son nom est mal écrit (attention aux majuscules et aux accents). |
        | `ModuleNotFoundError: No module named 'physique.py'; 'physique' is not a package` | On a écrit `import physique.py` : il ne faut **pas** mettre l'extension.                                                     |
        | `NameError: name 'calculer_poids' is not defined`                           | Avec `import physique`, on a oublié le préfixe : il faut écrire `physique.calculer_poids(...)`.                              |
        | `AttributeError: module 'random' has no attribute 'randint'`                | Vous avez nommé **votre** fichier `random.py` (ou `math.py`, etc.) : Python importe votre fichier au lieu du vrai module! Renommez-le. Python vous le suggère d'ailleurs à la fin du message : `(consider renaming '...\random.py' since it has the same name as the standard library module named 'random' ...)`. |

        :::

        ---

        :::note 📌 En résumé
        - Un **module** est un simple fichier `.py`; on l'importe avec son nom, **sans** `.py`.
        - `import` **exécute tout le fichier** du module, un peu comme un copier/coller, puis rend son contenu disponible.
        - La portée globale d'un module ne contient que des `import`, des **constantes** et des `def`.
        - Les tests et le code à exécuter vont dans `if __name__ == "__main__":`.
        :::

        :::info Appels

        Les fonctions peuvent appeler d'autres fonctions. \
        Cela est utile pour décomposer des tâches complexes en sous-tâches plus simples.

        ```python showLineNumbers
        def ajouter(x, y):
            return x + y

        def multiplier(x, y):
            return x * y

        def calculer_expression(a, b, c):
            somme = ajouter(a, b)
            resultat = multiplier(somme, c)
            return resultat

        valeur = calculer_expression(2, 3, 4)
        print(valeur)  # Affiche 20
        ```

        Dans cet exemple, la fonction `calculer_expression()` appelle les fonctions `ajouter()` et `multiplier()` pour effectuer une série de calculs.

        :::

        ---

        ::::note Pile d'appels

        Lorsque l'on démarre un programme Python, **une pile d'appels** est automatiquement créée. \
        Cette structure de données, généralement invisible sauf en cas d'erreur ou via des outils de débogage,
        permet à Python de suivre l'ordre d'exécution des fonctions et de conserver l'état des variables locales.

        🍽️ Imaginez une **pile d'assiettes** : on pose toujours une nouvelle assiette **sur le dessus**, et on retire toujours **celle du dessus**.

        **🔁 Fonctionnement de la pile**

        - Lorsqu'une instruction **appelle une fonction**, celle-ci est **empilée au sommet de la pile d'appels**.
        - Python exécute **une seule fonction à la fois**, toujours celle qui se trouve **en haut de la pile**.
        - Une fois l'exécution terminée (`return` ou fin du corps), **la fonction est retirée de la pile**.
        - La fonction qui se retrouve au sommet **reprend là où elle s'était arrêtée** : à la ligne de l'appel, avec la valeur retournée.

        **📚 Principe LIFO**

        La pile d'appels suit le principe LIFO (*Last In, First Out*, « dernier entré, premier sorti ») :
        - La dernière fonction **appelée** est la première à **se terminer** et à être retirée.
        - Ce mécanisme permet à Python de gérer les appels imbriqués de fonctions, et de revenir à l'état précédent une fois qu'une fonction a terminé son exécution.

        **🧱 La pile, étape par étape**

        Voici l'état de la pile pendant l'exécution de l'exemple `calculer_expression` ci-dessus (le **sommet** est à droite) :

        | Moment | Pile d'appels |
        |---|---|
        | Début du programme | `<module>` |
        | Ligne 12 : appel de `calculer_expression` | `<module>` → `calculer_expression` |
        | Ligne 8 : appel de `ajouter` | `<module>` → `calculer_expression` → `ajouter` |
        | `ajouter` retourne `5` | `<module>` → `calculer_expression` |
        | Ligne 9 : appel de `multiplier` | `<module>` → `calculer_expression` → `multiplier` |
        | `multiplier` retourne `20` | `<module>` → `calculer_expression` |
        | `calculer_expression` retourne `20` | `<module>` |

        :::tip-nt
        🕵️ `<module>`, c'est le nom que Python donne au **programme principal** (le code à l'extérieur de toute fonction). \
        C'est exactement ce que vous notez `globale` dans la colonne *contexte* de vos traces. Vous verrez `<module>` dans le débogueur et dans les messages d'erreur.
        :::

        **Un exemple avec un affichage**

        ```python showLineNumbers
        def fonction_a():
            print("Fonction A")
            fonction_b()
            print("Retour dans A")

        def fonction_b():
            print("Fonction B")

        fonction_a()
        ```

        La console affiche :
        ```
        Fonction A
        Fonction B
        Retour dans A
        ```

        Lorsque `fonction_a()` est appelée, elle appelle `fonction_b()`, qui est ajoutée au sommet de la pile. \
        Une fois que `fonction_b()` a terminé son exécution, elle est retirée, et `fonction_a()` **reprend** à la ligne 4 : « Retour dans A » s'affiche.

        👉 Remarquez que `fonction_b` est définie **après** `fonction_a`, et que ça fonctionne quand même : `fonction_a()` n'est appelée qu'à la ligne 9, quand les deux fonctions existent déjà. L'important, c'est que toutes les fonctions soient définies **avant le premier appel**.

        ::::

        ---

        :::danger 🔎 Le traceback, c'est la pile d'appels!
        Quand une erreur survient, Python affiche **l'état de la pile d'appels** à ce moment-là. Reprenons l'erreur de l'onglet [Portée](/cours/rencontre3?onglet=portee) :

        <Traceback>

        ```
        Traceback (most recent call last):
          File "...\r03_compteur.py", line 6, in <module>
            incrementer()
            ~~~~~~~~~~~^^
          File "...\r03_compteur.py", line 4, in incrementer
            compteur = compteur + 1
                       ^^^^^^^^
        UnboundLocalError: cannot access local variable 'compteur' where it is not associated with a value
        ```

        </Traceback>

        - Chaque `File ..., line ..., in ...` est **un étage de la pile** : `<module>` (le programme principal), puis `incrementer`.
        - *most recent call last* veut dire « l'appel le plus récent en dernier » : le **sommet de la pile est en bas**.
        - C'est pourquoi on lit un traceback **de bas en haut** : la dernière ligne donne l'erreur, l'étage juste au-dessus dit **dans quelle fonction** elle s'est produite, et les étages plus haut disent **qui a appelé** cette fonction.
        :::

        :::warning
        Le passage de fonctions en paramètre est une notion plus avancée qui dépasse le cadre de ce cours. \
        Elle n'est pas obligatoire pour réussir le cours, mais il s'agit d'un concept intéressant à explorer si vous êtes curieux.se. \
        Vous pouvez choisir de ne pas lire cette section si vous n'êtes pas assez à l'aise ou si vous êtes déjà assez mêlé.e comme ça!

        *Vous pouvez utiliser ou non cette notion pour réduire la quantité de code de la section **Comparaison des performances** du **TP1**.*
        :::

        ---

        :::info Les fonctions sont des valeurs

        En Python, une fonction est une **valeur** comme une autre (comme un `int` ou une `str`). Cela signifie que vous pouvez :
        1. Stocker une fonction dans une variable.
        2. Passer une fonction en **paramètre** à une autre fonction.

        Par exemple, pour le point 1 :
        ```python showLineNumbers
        def vers_kelvin(celsius):
            return celsius + 273.15

        conversion = vers_kelvin       # Pas de parenthèses : on stocke la fonction elle-même
        print(conversion(21.0))        # conversion contient une fonction : on peut l'appeler! Affiche 294.15
        ```

        👉 Vous vous souvenez de l'erreur « oublier les parenthèses » de l'onglet [Fonction](/cours/rencontre3?onglet=intro)? `print(double)` affichait `<function double at 0x…>`, c'est-à-dire **la fonction elle-même**. \
        Ici, on **omet volontairement** les parenthèses, justement pour manipuler la fonction sans l'appeler.
        :::

        ---

        :::tip-nt
        Imaginez un instrument de laboratoire qui lit une température en Celsius, mais qui doit pouvoir afficher le résultat dans différentes unités selon l'expérience en cours.
        :::

        ---

        ::::info Étape 1 : Créer des fonctions simples de transformation

        On commence par définir des fonctions simples qui font une seule tâche : la conversion.

        ```python showLineNumbers
        def vers_kelvin(celsius):
            return celsius + 273.15

        def vers_fahrenheit(celsius):
            return (celsius * 9/5) + 32
        ```
        ::::

        ---

        ::::info Étape 2 : Créer une fonction recevant une autre fonction en paramètre

        C'est ici que la magie opère. On crée une fonction qui accepte une valeur ET une **autre fonction** comme paramètre.

        ```python showLineNumbers
        # Le paramètre 'transformation' recevra une fonction (voir l'appel de cette fonction à l'étape #3)
        def afficher_resultat_labo(celsius, transformation):
            """
            Affiche la température lue par l'instrument, convertie avec la fonction reçue.

            Paramètres :
            celsius (float) : Température lue en degrés Celsius
            transformation (fonction) : Fonction de conversion qui reçoit une température en Celsius et retourne la valeur convertie

            Retourne :
            Rien (affiche le résultat)
            """
            # transformation contient une fonction : on peut donc l'appeler avec des parenthèses
            resultat = transformation(celsius)
            print(f"L'instrument affiche : {resultat}")
        ```

        👉 Remarquez la façon de documenter un paramètre qui reçoit une fonction : son type est `fonction`, et on décrit ce qu'elle doit **recevoir** et **retourner**.
        ::::

        ---

        ::::info Étape 3 : Appeler la fonction en lui passant une fonction en paramètre

        Lors de l'appel, on passe la fonction de conversion **sans les parenthèses**. \
        Si vous mettez des parenthèses, vous passez le *résultat* de la fonction au lieu de la fonction elle-même!

        ```python showLineNumbers
        temp_piece = 21.0

        # On passe 'vers_kelvin' comme une simple valeur
        print("--- Mode Scientifique ---")
        afficher_resultat_labo(temp_piece, vers_kelvin)

        # On change le comportement simplement en passant une autre fonction
        print("--- Mode Américain ---")
        afficher_resultat_labo(temp_piece, vers_fahrenheit)
        ```

        La console affiche :
        ```
        --- Mode Scientifique ---
        L'instrument affiche : 294.15
        --- Mode Américain ---
        L'instrument affiche : 69.8
        ```

        :::danger-nt
        ❌ **Avec des parenthèses :** `afficher_resultat_labo(temp_piece, vers_kelvin(temp_piece))` \
        `vers_kelvin(temp_piece)` est appelée **tout de suite** et donne `294.15`. C'est donc un **nombre** qui est passé dans `transformation`, et la ligne `transformation(celsius)` essaie d'appeler ce nombre :

        <Traceback>

        ```
        TypeError: 'float' object is not callable
        ```

        </Traceback>

        *not callable* veut dire « ne peut pas être appelé » : on ne peut pas mettre des parenthèses après un nombre!
        :::

        ::::

        ---

        :::note Pourquoi faire cela?

        Cela permet de créer une fonction « générique » (`afficher_resultat_labo()`) qui ne change jamais, même si vous ajoutez 50 nouveaux types de conversions plus tard. On sépare la **logique d'affichage** de la **logique de calcul**.

        🧪 **Mini-défi :** ajoutez une fonction `vers_rankine` ($R = (C + 273.15) \times 9/5$) et affichez la température de la pièce en Rankine. \
        Avez-vous dû modifier `afficher_resultat_labo`?
        :::

        ---

        :::info Code complet
        ```python showLineNumbers
        def vers_kelvin(celsius):
            return celsius + 273.15

        def vers_fahrenheit(celsius):
            return (celsius * 9/5) + 32

        def afficher_resultat_labo(celsius, transformation):
            resultat = transformation(celsius)
            print(f"L'instrument affiche : {resultat}")

        temp_piece = 21.0

        # On passe 'vers_kelvin' comme une simple valeur
        print("--- Mode Scientifique ---")
        afficher_resultat_labo(temp_piece, vers_kelvin)

        # On change le comportement simplement en passant une autre fonction
        print("--- Mode Américain ---")
        afficher_resultat_labo(temp_piece, vers_fahrenheit)
        ```
        :::

        ::::info Récursivité

        La récursivité est une technique de programmation où une fonction s'appelle elle-même pour résoudre un problème. \
        Cela peut être utile pour résoudre des problèmes qui peuvent être décomposés en sous-problèmes similaires.

        **Exemple : la factorielle**

        La factorielle d'un nombre $n$ (notée $n!$) est le produit de tous les entiers de $n$ jusqu'à 1 :
        $5! = 5 \times 4 \times 3 \times 2 \times 1 = 120$.

        💡 L'idée clé : $5! = 5 \times 4!$. Pour calculer la factorielle de 5, il suffit de connaître celle de 4… qui se calcule à partir de celle de 3, et ainsi de suite!

        Voici une fonction récursive qui calcule la factorielle d'un nombre : \
        (note : le code contient un `if` et un `or`, qui seront vus à la [rencontre 4](/cours/rencontre4), mais c'est pour illustrer la récursivité)

        ```python showLineNumbers
        def factorielle(n):
            if n == 0 or n == 1:  # Cas de base
                return 1
            else:
                return n * factorielle(n - 1)  # Appel récursif

        print(factorielle(5))  # Affiche 120
        ```

        Dans cet exemple, la fonction `factorielle` s'appelle elle-même avec un argument plus petit (`n - 1`) jusqu'à atteindre le cas de base (0 ou 1), où elle retourne 1.

        :::tip-nt
        🧩 **Les 2 ingrédients d'une fonction récursive**
        1. Un **cas de base**, qui arrête les appels (ici : `n` vaut 0 ou 1).
        2. Un **appel qui se rapproche** du cas de base (ici : `n - 1`).

        Une récursion sans cas de base, c'est comme une boucle `while` dont la condition ne devient jamais fausse (voir la [rencontre 4](/cours/rencontre4?onglet=while)).
        :::

        ::::

        ---

        :::info 🧱 La pile d'appels, étape par étape
        Voici l'état de la [pile d'appels](/cours/rencontre3?onglet=pile) pendant le calcul de `factorielle(5)` (le **sommet** est à droite) :

        | Moment | Pile d'appels |
        |---|---|
        | Appel de `factorielle(5)` | `<module>` → `factorielle(5)` |
        | `factorielle(5)` appelle `factorielle(4)` | `<module>` → `factorielle(5)` → `factorielle(4)` |
        | … | … |
        | Appel de `factorielle(1)` : **cas de base** | `<module>` → `factorielle(5)` → `factorielle(4)` → `factorielle(3)` → `factorielle(2)` → `factorielle(1)` |
        | `factorielle(1)` retourne `1` | `<module>` → `factorielle(5)` → `factorielle(4)` → `factorielle(3)` → `factorielle(2)` |
        | `factorielle(2)` retourne `2 * 1 = 2` | `<module>` → `factorielle(5)` → `factorielle(4)` → `factorielle(3)` |
        | `factorielle(3)` retourne `3 * 2 = 6` | `<module>` → `factorielle(5)` → `factorielle(4)` |
        | `factorielle(4)` retourne `4 * 6 = 24` | `<module>` → `factorielle(5)` |
        | `factorielle(5)` retourne `5 * 24 = 120` | `<module>` |

        👉 La pile **se remplit** à l'aller (les appels), puis **se vide** au retour (les valeurs retournées remontent).

        🕵️ Au plus profond, il y a **5 variables `n` différentes** dans la pile, une par appel (5, 4, 3, 2 et 1) : chaque appel a ses propres variables locales (voir l'onglet [Portée](/cours/rencontre3?onglet=portee)). Dans une trace, chacune aurait sa colonne!

        🐞 Pour l'observer vous-même : mettez un point d'arrêt à la ligne 7, puis appuyez sur **Step Into** à répétition. Regardez la pile d'appels grandir, puis diminuer.
        :::

        ---

        :::danger Sans cas de base : `RecursionError`
        Si on oublie le cas de base, la fonction s'appelle **à l'infini** :
        ```python showLineNumbers
        def factorielle(n):
            return n * factorielle(n - 1)  # ❌ Aucun cas de base!

        print(factorielle(5))
        ```
        Python arrête le programme après environ 1000 appels :

        <Traceback>

        ```
        Traceback (most recent call last):
          File "...\r03_recursion.py", line 4, in <module>
            print(factorielle(5))
                  ~~~~~~~~~~~^^^
          File "...\r03_recursion.py", line 2, in factorielle
            return n * factorielle(n - 1)
                       ~~~~~~~~~~~^^^^^^^
          [Previous line repeated 996 more times]
        RecursionError: maximum recursion depth exceeded
        ```

        </Traceback>

        👉 Le traceback **est** la pile d'appels : elle est si haute que Python la résume (*Previous line repeated 996 more times*).

        ⚠️ Même avec le cas de base, `factorielle(-1)` donne la même erreur : en soustrayant 1 à partir de -1, on n'atteint **jamais** 0 ou 1! Il faudrait valider le paramètre avec un `raise` (voir la [rencontre 4](/cours/rencontre4?onglet=exceptions-validation)).
        :::

        Tout ce qu'on fait par récursivité peut aussi se faire avec une **boucle** (rencontres 4 et 5). C'est l'approche utilisée dans ce cours.
        :::
