        :::info Qu'est-ce qu'une expression booléenne?

        Une expression booléenne est une expression qui s'évalue à une valeur de vérité ([`bool`](/aidememoire/types/)), c'est-à-dire soit `True` (vrai), soit `False` (faux). \
        Elles servent à prendre des décisions dans le code : dans les structures conditionnelles (`if`, `elif`) et dans les boucles `while`.

        :::

        ---

        :::note Opérateurs de comparaison et opérateurs logiques

        - Les opérateurs **de comparaison** (`==`, `!=`, `<`, `>`, `<=`, `>=`) comparent deux valeurs.
        - Les opérateurs **logiques** (`and`, `or`, `not`) combinent plusieurs expressions booléennes.

        <AideMemoireExpressionsBoolennes />

        :::

        ---

        :::danger ⚠️ Ne pas confondre `=` et `==`
        - `=` **affecte** une valeur à une variable : `x = 5` (« x reçoit 5 »).
        - `==` **compare** deux valeurs : `x == 5` (« x est-il égal à 5? »), ce qui donne `True` ou `False`.

        ```python
        if x = 5:     # ❌ SyntaxError : on ne peut pas affecter dans une condition
        if x == 5:    # ✅ On compare
        ```
        :::

        ---

        :::tip Exemples d'utilisation
        ```python showLineNumbers
        a = 5
        b = 10
        print(a < b)               # Affiche True
        print(a == b)              # Affiche False
        print(a + 5 >= b * 2 - 12) # Affiche True, explications ci-dessous!
        ```

        Les deux opérandes d'un opérateur de comparaison peuvent être le résultat d'autres expressions. \
        Python évalue l'expression selon la [priorité des opérateurs](/aidememoire/operateurs?onglet=priorite), en remplaçant chaque sous-expression par sa valeur.

        Voici comment Python évalue l'instruction de la ligne 5, étape par étape :

        ```python
        print(a + 5 >= b * 2 - 12)   # Instruction originale
        print(5 + 5 >= b * 2 - 12)   # Remplace 'a' par sa valeur
        print(10 >= b * 2 - 12)      # Calcule la somme 5 + 5
        print(10 >= 10 * 2 - 12)     # Remplace 'b' par sa valeur
        print(10 >= 20 - 12)         # La multiplication passe avant la soustraction
        print(10 >= 8)               # Calcule la soustraction
        print(True)                  # La comparaison est faite en dernier
        ```
        :::

        ---

        :::info Les opérateurs logiques : table de vérité
        Les opérateurs logiques combinent des expressions booléennes. Leur résultat ne dépend que des valeurs `True`/`False` qu'on leur donne :

        | `A` | `B` | `A and B` | `A or B` | `not A` |
        |:---:|:---:|:---:|:---:|:---:|
        | `True` | `True` | `True` | `True` | `False` |
        | `True` | `False` | `False` | `True` | `False` |
        | `False` | `True` | `False` | `True` | `True` |
        | `False` | `False` | `False` | `False` | `True` |

        - `and` donne `True` seulement si **les deux** sont `True`.
        - `or` donne `True` si **au moins un** est `True`.
        - `not` **inverse** la valeur.

        Exemple : une solution est acide si son pH est d'au moins 0 **et** plus petit que 7.
        ```python showLineNumbers
        ph = 4.2
        est_acide = ph >= 0 and ph < 7
        print(est_acide)       # True  (True and True)
        print(not est_acide)   # False
        ```
        :::

        ---

        :::tip Comparaisons enchaînées
        En Python, on peut enchaîner les comparaisons comme en mathématiques :
        ```python
        print(0 <= ph < 7)     # Équivalent à : ph >= 0 and ph < 7
        ```
        C'est très pratique pour vérifier qu'une valeur est **dans un intervalle**, par exemple `0 < n < 1`.
        :::

        ---

        :::warning Attention à l'égalité entre nombres à virgule
        ```python
        print(0.1 + 0.2 == 0.3)            # False!
        print(round(0.1 + 0.2, 2) == 0.3)  # True
        ```
        Les nombres à virgule (`float`) ne sont pas toujours représentés exactement (voir l'onglet [Précision des flottants](/cours/rencontre2?onglet=precision-flottants) de la rencontre 2). \
        Pour comparer des `float`, arrondissez-les d'abord à la précision voulue.
        :::

        ---

        :::info Priorité des opérateurs
        La priorité des opérateurs détermine l'ordre dans lequel les opérations sont effectuées dans une expression. \
        En Python, la priorité est la suivante (de la plus haute à la plus basse) :
        1. Parenthèses `()`
        2. Opérateurs arithmétiques (`**`, puis `*`, `/`, `//`, `%`, puis `+`, `-`)
        3. Opérateurs de comparaison (`==`, `!=`, `<`, `<=`, `>`, `>=`)
        4. Opérateur `not`
        5. Opérateur `and`
        6. Opérateur `or`

        Un ordre plus exhaustif des priorités des opérateurs est disponible [ici dans l'aide-mémoire](/aidememoire/operateurs?onglet=priorite).
        :::

        ---

        :::tip Exemple de priorité
        ```python showLineNumbers
        a = 5
        b = 10
        c = 15
        print(a < b and b < c)  # Évalué comme (a < b) and (b < c), affiche True
        print(a < b or b > c)   # Évalué comme (a < b) or (b > c), affiche True
        print(not a < b)        # Évalué comme not (a < b), affiche False

        # Les parenthèses peuvent changer le résultat :
        print(a > b and b > c or a == 5)    # (False and False) or True  → True
        print(a > b and (b > c or a == 5))  # False and (False or True)  → False
        ```
        Sans parenthèses, le `and` est évalué **avant** le `or`. En cas de doute, ajoutez des parenthèses : votre code sera aussi plus facile à lire.
        :::

        ---

        :::info Stockage dans des variables
        On peut stocker le résultat d'une expression booléenne dans une variable pour une utilisation ultérieure.
        ```python showLineNumbers
        a = 5
        b = 10
        est_plus_petit = a < b  # est_plus_petit sera True
        est_egal = a == b       # est_egal sera False
        print(est_plus_petit)   # Affiche True
        print(est_egal)         # Affiche False
        ```
        :::

    <TabItem value="if" label="if">

        :::info On veut pas le sawouère, on veut le wouère
        C'est bien beau, ça, les expressions booléennes, mais à quoi ça sert?<br />
        👉 Elles servent principalement à contrôler le flux d'exécution du programme, \
        c'est-à-dire à décider quelles parties du code doivent être exécutées en fonction de certaines conditions.
        :::

        ---

        :::tip Structure de base d'une instruction conditionnelle
        Voici un exemple simple d'instruction conditionnelle en Python :
        ```python showLineNumbers
        age = 18
        if age >= 18:
            print("Vous êtes majeur.")
        ```
        Dans cet exemple, l'instruction `if` vérifie si la variable `age` est supérieure ou égale à 18.<br />
        Si c'est le cas (si la condition est `True`), le code indenté sous l'instruction `if` est exécuté, affichant "Vous êtes majeur.".<br />
        Si la condition est `False`, le code indenté n'est pas exécuté.

        Exécutez ce code en mode débogage avec `age = 18`, puis avec `age = 15` : avancez une ligne à la fois et observez que la ligne 3 est **sautée** quand la condition est fausse.
        :::

        ---

        :::warning Indentation
        En Python, l'indentation (les espaces ou tabulations avant une ligne de code) est cruciale pour définir les blocs de code.<br />
        Le code qui doit être exécuté conditionnellement doit être indenté sous l'instruction `if`.<br />
        Par exemple :
        ```python showLineNumbers
        if condition:
            # Code indenté, exécuté si la condition est True
            faire_quelque_chose_conditionnel()
            faire_autre_chose_conditionnel()
        # Code non indenté, exécuté indépendamment de la condition
        faire_autre_chose_en_tout_temps()
        ```
        Exemple d'erreur courante due à une mauvaise indentation :
        ```python showLineNumbers
        if condition:
        faire_quelque_chose()  # Erreur : cette ligne doit être indentée
        ```
        Autre erreur fréquente : **oublier le deux-points** à la fin de la ligne du `if`.
        ```python showLineNumbers
        if age >= 18     # ❌ SyntaxError: expected ':'
            print("Vous êtes majeur.")
        ```
        Exemple concret :
        ```python showLineNumbers
        age = 20
        if age >= 18:
            print("Vous êtes majeur.")
            print("Vous avez le droit de vote!")
            print("Un grand pouvoir implique de grandes responsabilités.")
        print("Bienvenue!")  # Toujours exécuté, indépendamment de l'âge
        ```
        :::

    <TabItem value="elif" label="elif">

        :::info Un elfe?
        Non!<br />
        `elif` est la contraction de "else if", qui signifie "sinon si".<br />
        Elle permet de vérifier une autre condition si la première condition dans l'instruction `if` est `False`.

        Par exemple :
        ```python showLineNumbers
        age = 16
        if age >= 18:
            print("Vous êtes majeur.")
        elif age >= 13:
            print("Vous êtes adolescent.")
        ```
        :::

        ---

        :::note Multiple elif
        On peut avoir plusieurs clauses `elif` pour vérifier plusieurs conditions différentes.<br />
        Par exemple :
        ```python showLineNumbers
        age = 10
        if age >= 18:
            print("Vous êtes majeur.")
        elif age >= 13:
            print("Vous êtes adolescent.")
        elif age >= 3:
            print("Vous êtes un enfant.")
        ```
        Que se passe-t-il avec `age = 2`? Aucune condition n'est vraie : **aucun bloc n'est exécuté** et rien n'est affiché. \
        Pour prévoir un bloc exécuté « dans tous les autres cas », on utilise `else` (onglet suivant).
        :::

        ---

        :::tip Ordre des conditions
        L'ordre des conditions est important.<br />
        Les conditions sont évaluées de haut en bas, et la première condition qui est `True` déclenche l'exécution du bloc de code correspondant.<br />
        Par exemple, dans le code suivant, la condition `age >= 13` sera toujours `True` pour tous les adultes, et la condition `age >= 18` ne sera jamais atteinte :
        ```python showLineNumbers
        age = 21
        if age >= 13:
            print("Vous êtes adolescent.")
        elif age >= 18:
            print("Vous êtes majeur.")
        ```
        Pour éviter cela, placez les conditions **du cas le plus précis au cas le plus général** : ici, `age >= 18` est plus précis que `age >= 13` (tous les majeurs ont aussi au moins 13 ans), il doit donc être vérifié en premier :
        ```python showLineNumbers
        age = 21
        if age >= 18:
            print("Vous êtes majeur.")
        elif age >= 13:
            print("Vous êtes adolescent.")
        ```
        👉 Avec `<`, l'ordre s'inverse : on commence par la plus petite borne (`if age < 3`, puis `elif age < 13`, puis `elif age < 18`).
        :::

        ---

        :::warning Pas de `elif` sans `if`
        Une clause `elif` doit toujours être précédée d'une instruction `if`.<br />
        Par exemple, le code suivant est incorrect et provoquera une erreur de syntaxe :
        ```python showLineNumbers
        age = 16
        elif age >= 13:  # Erreur : 'elif' sans 'if'
            print("Vous êtes adolescent.")
        ```
        :::

    <TabItem value="else" label="else">

        :::info Le sinon
        `else` signifie "sinon".<br />
        Elle permet de définir un bloc de code qui sera exécuté si toutes les conditions précédentes (`if` et `elif`) sont `False`.

        Par exemple :
        ```python showLineNumbers
        age = 10
        if age >= 18:
            print("Vous êtes majeur.")
        elif age >= 13:
            print("Vous êtes adolescent.")
        else:
            print("Vous êtes un enfant.")
        ```
        Dans cet exemple, si `age` est inférieur à 13, le message "Vous êtes un enfant." sera affiché.
        :::

        ---

        :::tip Utilisation avec if et elif
        La clause `else` est souvent utilisée à la fin d'une série d'instructions `if` et `elif` pour capturer tous les cas non couverts par les conditions précédentes.<br />
        Par exemple :
        ```python showLineNumbers
        score = 85
        if score >= 90:
            print("Excellent")
        elif score >= 75:
            print("Bien")
        elif score >= 50:
            print("Passable")
        else:
            print("Échec")
        ```
        :::

        ---

        :::warning Pas de condition avec else
        Contrairement à `if` et `elif`, la clause `else` ne prend pas de condition.<br />
        Elle est simplement exécutée si toutes les conditions précédentes sont `False`. Par exemple, le code suivant est incorrect et provoquera une erreur de syntaxe :
        ```python showLineNumbers
        score = 85
        if score >= 90:
            print("Excellent")
        elif score >= 75:
            print("Bien")
        elif score >= 50:
            print("Passable")
        else score < 50:  # Erreur : 'else' ne doit pas avoir de condition
            print("Échec")
        ```
        :::

        ---

        :::tip else sans elif
        Il est possible d'utiliser `else` directement après un `if`, sans avoir besoin de `elif`.<br />
        Par exemple :
        ```python showLineNumbers
        age = 20
        if age >= 18:
            print("Vous êtes majeur.")
        else:
            print("Vous êtes mineur.")
        ```
        :::

        ---

        :::info Intégration avec les fonctions et les listes

        Les structures conditionnelles (`if/elif/else`, `match/case`) peuvent être utilisées à l'intérieur de fonctions.

        **Exemple 1 — `if/else` simple :**
        ```python showLineNumbers
        def est_pair(n):
            if n % 2 == 0:
                return True  # Faire modulo 2 sur un nombre pair donne toujours 0!
            else:
                return False
        
        a = 33
        b = 52
        print(f"{a} est un nombre pair : {est_pair(a)}")
        print(f"{b} est un nombre pair : {est_pair(b)}")
        ```

        ```
        33 est un nombre pair : False
        52 est un nombre pair : True
        ```
        💡 Puisque `n % 2 == 0` donne déjà `True` ou `False`, on peut retourner directement le résultat de la comparaison :
        ```python
        def est_pair(n):
            return n % 2 == 0
        ```
        **Exemple 2 — `if` avec paramètre optionnel et calcul par palier :**

        La fonction suivante calcule la paie brute d'un employé. Elle accepte un troisième paramètre optionnel pour activer le calcul des heures supplémentaires au taux double.

        ```python showLineNumbers
        def calculer_paie_brute(nb_heures, taux_horaire, temps_double_apres_40_heures=False):
            salaire = nb_heures * taux_horaire
            if temps_double_apres_40_heures and nb_heures >= 40:
                nb_heures_temps_supp = nb_heures - 40
                salaire = salaire + nb_heures_temps_supp * taux_horaire * 2
            return salaire

        nb_heures = 45
        taux_horaire = 20
        print(f"Calcul de la paie brute pour {nb_heures} heures à un taux horaire de {taux_horaire}$/h.")
        print(f"  Avec le temps > 40 payé au taux doublé   : {calculer_paie_brute(nb_heures, taux_horaire, True)}$")
        print(f"  Avec le temps > 40 payé au taux régulier : {calculer_paie_brute(nb_heures, taux_horaire)}$")
        ```

        ```
        Calcul de la paie brute pour 45 heures à un taux horaire de 20$/h.
          Avec le temps > 40 payé au taux doublé   : 1100$
          Avec le temps > 40 payé au taux régulier : 900$
        ```

        **Exemple 3 — `if/elif/else` avec trois listes parallèles :**

        On peut stocker plusieurs valeurs dans des **listes parallèles** et appeler notre fonction sur chaque élément.
        Voici une liste d'éléments du tableau périodique avec leur masse atomique (en u.m.a.) et leur nombre de protons.
        On veut **classifier la stabilité** de chaque noyau en fonction du rapport entre sa masse atomique et son nombre de protons — un indicateur simplifié du ratio neutrons/protons :

        ```python showLineNumbers
        def stabilite_noyau(masse_atomique, nb_protons):
            """
            Classifie la stabilité d'un noyau selon le ratio neutrons/protons.

            Paramètres :
            masse_atomique (int) : Nombre de masse de l'élément (protons + neutrons).
            nb_protons (int)     : Nombre de protons dans le noyau.

            Retourne :
            str : "stable", "légèrement instable" ou "très instable".
            """
            nb_neutrons = masse_atomique - nb_protons
            ratio = nb_neutrons / nb_protons
            if ratio <= 1.1:
                return "stable"
            elif ratio <= 1.5:
                return "légèrement instable"
            else:
                return "très instable"

        masses_atomiques = [1,4,7,12,14,16]
        symboles = ["H","He","Li","C","N","O"]
        nb_protons = [1,2,3,6,7,8]

        print(f"{symboles[0]} (masse {masses_atomiques[0]}) - stabilité : {stabilite_noyau(masses_atomiques[0], nb_protons[0])}")
        print(f"{symboles[1]} (masse {masses_atomiques[1]}) - stabilité : {stabilite_noyau(masses_atomiques[1], nb_protons[1])}")
        print(f"{symboles[2]} (masse {masses_atomiques[2]}) - stabilité : {stabilite_noyau(masses_atomiques[2], nb_protons[2])}")
        print(f"{symboles[3]} (masse {masses_atomiques[3]}) - stabilité : {stabilite_noyau(masses_atomiques[3], nb_protons[3])}")
        print(f"{symboles[4]} (masse {masses_atomiques[4]}) - stabilité : {stabilite_noyau(masses_atomiques[4], nb_protons[4])}")
        print(f"{symboles[5]} (masse {masses_atomiques[5]}) - stabilité : {stabilite_noyau(masses_atomiques[5], nb_protons[5])}")
        ```

        ```
        H (masse 1) - stabilité : stable
        He (masse 4) - stabilité : stable
        Li (masse 7) - stabilité : légèrement instable
        C (masse 12) - stabilité : stable
        N (masse 14) - stabilité : stable
        O (masse 16) - stabilité : stable
        ```

        👉 On remarque qu'on répète 6 fois la même instruction `print` en changeant seulement l'index. \
        C'est exactement le genre de répétition qu'une **boucle `for`** éliminera en quelques lignes, vous verrez ça bientôt!

        :::

    <TabItem value="comparaison" label="if ou elif?">


        :::danger ⚠️ `if if if` vs `if elif else` — ce n'est pas la même chose!

        C'est l'une des erreurs les plus fréquentes chez les débutants : \
        utiliser plusieurs `if` indépendants là où un `if/elif/else` serait nécessaire. \
        La différence est fondamentale : le programme peut afficher un **résultat faux**.

        Prenons cet exemple avec `score = 95` :

        ```python showLineNumbers
        # Version avec des if if if
        score = 95
        if score >= 90:
            print("Excellent")  # ✅ Exécuté (95 >= 90 est True)
        if score >= 75:
            print("Bien")       # ✅ Exécuté (95 >= 75 est True)
        if score >= 50:
            print("Passable")   # ✅ Exécuté (95 >= 50 est True)
        else:
            print("Échec")      # ⏭️ Bloc ignoré (car la condition score >= 50 a donné True)
        ```

        Résultat affiché :
        ```
        Excellent
        Bien
        Passable
        ```
        👉 Avec des `if` indépendants, Python évalue **chaque condition séparément**, de haut en bas, **sans jamais s'arrêter**. Comme les 3 conditions sont `True` pour `score = 95`, les **3 blocs sont exécutés**. Ce n'est presque certainement pas ce qu'on voulait! Il aurait été préférable que Python arrête d’évaluer les autres conditions dès qu’il trouve une condition donnant `True`.

        :::

        ---

        :::tip ✅ La bonne approche : `if elif else`
        ```python showLineNumbers
        # Version avec if elif else
        score = 95
        if score >= 90:
            print("Excellent")  # ✅ Exécuté (95 >= 90 est True) → Python arrête ici
        elif score >= 75:
            print("Bien")       # ⏭️ Bloc ignoré (car une condition d'un bloc précédent a donné True)
        elif score >= 50:
            print("Passable")   # ⏭️ Bloc ignoré (car une condition d'un bloc précédent a donné True)
        else:
            print("Échec")      # ⏭️ Bloc ignoré (car une condition d'un bloc précédent a donné True)
        ```

        Résultat affiché :
        ```
        Excellent
        ```

        👉 Avec `if/elif/else`, dès qu'une condition est `True`, Python exécute le bloc correspondant et **saute immédiatement le reste** : les autres conditions ne sont **jamais évaluées**. Un seul bloc s'exécute, peu importe le nombre de `elif`. Python a donc exécuté uniquement le bloc associé à `score >= 90`.
        :::

        ---

        :::note 🧠 Comment choisir entre les 2 approches

        | Situation | Utiliser |
        |-----------|----------|
        | Les cas sont **mutuellement exclusifs** (un seul doit s'exécuter) | <C><K>if</K> &#47; <K>elif</K> &#47; <K>else</K></C> |
        | Les vérifications sont **indépendantes** les unes des autres | Plusieurs <C><K>if</K></C> séparés |

        **Exemple où plusieurs `if` séparés sont appropriés** :
        ```python showLineNumbers
        ph = 3.5
        temperature_celsius = 85
        pression_atm = 1.8

        if ph < 6:
            print("⚠️ Solution acide : portez des gants de protection.")       # ✅ Exécuté
        if temperature_celsius > 60:
            print("🌡️ Température élevée : risque de brûlure.")                # ✅ Exécuté
        if pression_atm > 1.5:
            print("💨 Pression élevée : vérifiez l'étanchéité du système.")    # ✅ Exécuté
        ```
        Ici, les 3 avertissements sont **complémentaires** et ont du sens ensemble. Plusieurs `if` indépendants sont donc le bon choix.

        :::

        ---

        :::info Récapitulatif if, elif, else

        Pour récapituler, la structure d'une instruction conditionnelle en Python est la suivante :
        1. `if` : Obligatoire pour commencer une instruction conditionnelle.
        2. `elif` : Les blocs `elif` sont optionnels.
            - Il peut y en avoir 0, 1, 2 ou plus.
            - Chaque `elif` vérifie une condition, seulement si toutes les conditions précédentes sont `False`.
        3. `else` : Le bloc `else` est optionnel.
            - Il ne peut y avoir qu’un seul `else`.
            - Il est exécuté si toutes les conditions précédentes sont `False`.
            - Le bloc `else` ne prend pas de condition.
        4. Les conditions sont évaluées **de haut en bas** : dès qu'une condition est `True`, son bloc est exécuté et les suivantes sont ignorées.
        5. Le code de chaque bloc doit être **indenté** sous la ligne `if`, `elif` ou `else` correspondante.
        :::

    </TabItem>

    <TabItem value="imbrication" label="Imbrication">

        :::info Des conditions dans des conditions!
        Il est tout à fait possible d'écrire une structure conditionnelle **à l'intérieur** d'une autre.\
        On appelle cela des structures **imbriquées** (*nested* en anglais).

        C'est utile quand une décision dépend d'une autre, comme dans la vraie vie!
        :::

        :::tip Exemple de base — classer un échantillon
        Imaginons qu'on veuille classer un échantillon selon son pH **ET** sa température :

        ```python showLineNumbers
        ph = 4.2
        temperature_celsius = 75

        if ph < 7:
            print("Solution acide.")
            if temperature_celsius > 60:               # Condition imbriquée dans le if
                print("⚠️ Acide ET chaude : danger!")
            else:
                print("Acide mais à température normale.")
        else:
            print("Solution neutre ou basique.")
            if temperature_celsius > 60:               # Condition imbriquée dans le else
                print("⚠️ Solution chaude : manipuler avec précaution.")
            else:
                print("Conditions stables.")
        ```

        Résultat affiché avec `ph = 4.2` et `temperature_celsius = 75` :
        ```
        Solution acide.
        ⚠️ Acide ET chaude : danger!
        ```

        👉 Python entre d'abord dans le bloc `if ph < 7`, puis évalue la condition sur la température **seulement à l'intérieur de ce bloc**.
        :::

        :::note L'indentation, encore plus importante avec l'imbrication!
        Chaque niveau d'imbrication ajoute **un niveau d'indentation supplémentaire**.\
        C'est ce qui permet à Python de savoir à quel bloc appartient chaque instruction.

        ```python showLineNumbers
        if condition_1:
            # Bloc de la condition 1 (indenté 1 fois)
            if condition_2:
                # Bloc de la condition 2 (indenté 2 fois)
                faire_quelque_chose()
            else:
                # Bloc else de la condition 2 (indenté 2 fois)
                faire_autre_chose()
        else:
            # Bloc else de la condition 1 (indenté 1 fois)
            faire_encore_autre_chose()
        ```

        :::

        :::tip Exemple concret — classification d'une étoile 🌟
        En astronomie, on peut classer une étoile selon sa **luminosité** et sa **température de surface** :

        ```python showLineNumbers
        luminosite = 500        # En unités solaires
        temperature_K = 8000    # En kelvins

        if luminosite >= 100:
            print("Étoile très lumineuse.")
            if temperature_K >= 10000:
                print("⭐ Classification : étoile bleue géante.")
            elif temperature_K >= 6000:
                print("⭐ Classification : étoile blanche géante.")
            else:
                print("⭐ Classification : supergéante froide.")
        elif luminosite >= 1:
            print("Étoile de luminosité moyenne.")
            if temperature_K >= 6000:
                print("⭐ Classification : étoile de la séquence principale (type solaire ou plus chaud).")
            else:
                print("⭐ Classification : étoile naine froide.")
        else:
            print("Étoile peu lumineuse.")
            if temperature_K >= 4000:
                print("⭐ Classification : naine blanche.")
            else:
                print("⭐ Classification : naine brune.")
        ```

        Résultat affiché avec `luminosite = 500` et `temperature_K = 8000` :
        ```
        Étoile très lumineuse.
        ⭐ Classification : étoile blanche géante.
        ```

        👉 Le premier `if/elif/else` traite la luminosité, puis, à l'intérieur de **chacun** de ses blocs, un second `if/elif/else` affine la classification selon la température.
        :::

        :::tip Un `if/else` seul dans un `else`? Utilisez `elif`!
        Quand le bloc `else` ne contient **qu'un** `if/else`, on peut le remplacer par un `elif` et retirer un niveau d'indentation :
        ```python showLineNumbers
        # Imbriqué
        if ph < 7:
            print("Acide")
        else:
            if ph == 7:
                print("Neutre")
            else:
                print("Basique")
        ```
        ```python showLineNumbers
        # Équivalent, plus lisible
        if ph < 7:
            print("Acide")
        elif ph == 7:
            print("Neutre")
        else:
            print("Basique")
        ```
        👉 L'imbrication est utile quand le bloc contient **autre chose** que la condition imbriquée (comme le `print("Solution acide.")` de l'exemple de base).
        :::

        ---

        :::warning Attention à la profondeur d'imbrication!
        Plus on imbrique de niveaux, plus le code devient difficile à lire et à déboguer.\
        En général, une bonne règle de base est de ne pas dépasser **2 à 3 niveaux**.\
        Si vous vous retrouvez avec plus de 3 niveaux, c'est souvent le signe que le code pourrait être réorganisé, par exemple en utilisant des fonctions.

        ```python showLineNumbers
        # ❌ Difficile à lire — trop de niveaux d'imbrication
        if condition_1:
            if condition_2:
                if condition_3:
                    if condition_4:
                        faire_quelque_chose()  # On s'y perd!
        ```

        ```python showLineNumbers
        # ✅ Plus lisible — on peut souvent combiner les conditions avec and
        if condition_1 and condition_2 and condition_3 and condition_4:
            faire_quelque_chose()
        ```
        :::

        :::note 🧠 Quand utiliser l'imbrication?

        | Situation | Approche recommandée |
        |-----------|----------------------|
        | La 2e condition ne s'évalue **que si** la 1re est vraie | **Imbrication** |
        | Les conditions sont **indépendantes** les unes des autres | Plusieurs <C><K>if</K></C> séparés |
        | Les conditions peuvent être combinées simplement | <C><K>and</K></C> / <C><K>or</K></C> dans un seul <C><K>if</K></C> |

        👉 L'imbrication est le bon choix quand la **logique est hiérarchique** : on vérifie d'abord une catégorie générale, puis on affine à l'intérieur de cette catégorie.
        :::

    <TabItem value="exceptions-validation" label="raise">

        :::info Pourquoi valider les paramètres?
        Quand on écrit une fonction, il faut s'assurer que les **entrées** (paramètres) ont du sens. \
        Sinon, on risque d'obtenir des résultats absurdes ou des erreurs difficiles à comprendre.

        Comparez ces deux versions :

        ```python showLineNumbers
        # Version 1 – sans validation
        def vitesse_moyenne(distance, temps):
            return distance / temps

        print(vitesse_moyenne(100, 20))  # ✅ 5.0
        print(vitesse_moyenne(-50, 10))  # ⚠️ -5.0 m/s sans avertissement (résultat absurde), le programme continue malgré tout!
        print(vitesse_moyenne(100, 0))   # ❌ Erreur Python brute (ZeroDivisionError: division by zero), le programme arrête ici!
        ```

        ```python showLineNumbers
        # Version 2 – avec validation
        def vitesse_moyenne(distance, temps):
            if distance < 0:
                raise ValueError("La distance ne peut pas être négative.")
            if temps == 0:
                raise ZeroDivisionError("Le temps ne peut pas être nul.")
            if temps < 0:
                raise ValueError("Le temps ne peut pas être négatif.")
            return distance / temps

        print(vitesse_moyenne(100, 20))  # ✅ 5.0
        print(vitesse_moyenne(-50, 10))  # ❌ ValueError: La distance ne peut pas être négative. Message clair, le programme arrête ici!
        print(vitesse_moyenne(100, 0))   # Jamais atteint : le programme s'est arrêté à la ligne précédente
        ```

        👉 La version 2 donne des **messages d'erreur explicites**, évite les résultats absurdes et rend le code **plus robuste et réutilisable**.
        :::

        ---

        :::note `raise` — mettre une barrière dans une fonction
        `raise` permet de **provoquer volontairement une erreur** lorsqu'une condition n'est pas respectée. \
        C'est la façon de signaler au programmeur qui appelle la fonction qu'il l'utilise avec de mauvaises valeurs.

        Dans la version 2 de `vitesse_moyenne` :
        - chaque `if` vérifie **une** contrainte sur les paramètres;
        - si la contrainte n'est pas respectée, `raise` lève une exception avec un **message qui explique le problème**;
        - Python **interrompt immédiatement** la fonction (comme un `return`) : les lignes suivantes, dont le calcul, ne sont jamais exécutées.
        :::

        ---

        :::info 🔎 Lire le message d'erreur dans la console
        Quand une exception n'est pas attrapée, Python affiche un bloc rouge appelé ***traceback***. Il se lit **de bas en haut**. Voici celui obtenu avec la version 2 de `vitesse_moyenne` ci-dessus :

        <div className="traceback">

        ```
        Traceback (most recent call last):
          File "...\r04_vitesse.py", line 12, in <module>
            print(vitesse_moyenne(-50, 10))
                  ~~~~~~~~~~~~~~~^^^^^^^^^
          File "...\r04_vitesse.py", line 4, in vitesse_moyenne
            raise ValueError("La distance ne peut pas être négative.")
        ValueError: La distance ne peut pas être négative.
        ```

        </div>

        1. **La dernière ligne** donne le **type** d'exception (`ValueError`) et le **message** : c'est ce qu'il faut lire en premier.
        2. **Juste au-dessus** : la ligne qui a levé l'exception (ligne 4, dans la fonction `vitesse_moyenne`).
        3. **Plus haut** : d'où la fonction a été appelée (ligne 12). C'est souvent là que se trouve la cause, ici une distance négative passée en argument.

        👉 C'est pour ça qu'un **message utile** dans `raise` est si important : c'est la première chose que lira la personne qui utilise votre fonction.
        :::

        ---

        :::tip Valider un intervalle
        Pour vérifier qu'une valeur est **comprise entre deux bornes**, on combine `not` et une [comparaison enchaînée](/cours/rencontre4?onglet=expressions) :

        ```python showLineNumbers
        def classer_solution(ph):
            if not 0 <= ph <= 14:
                raise ValueError("Le pH doit être compris entre 0 et 14.")
            if ph < 7:
                return "acide"
            elif ph == 7:
                return "neutre"
            else:
                return "basique"

        print(classer_solution(4.2))   # acide
        print(classer_solution(15))    # ❌ ValueError: Le pH doit être compris entre 0 et 14.
        ```
        `0 <= ph <= 14` est `True` si le pH est valide; `not` inverse le résultat pour lever l'exception seulement quand il est **hors** de l'intervalle.
        :::

        ---

        :::tip Et si on ne veut pas que le programme s'arrête?
        Avec `raise`, une erreur **arrête le programme** avec un message clair : c'est voulu, puisque la fonction a été mal utilisée. \
        À la [rencontre 5](/cours/rencontre5?onglet=try-except), vous verrez comment **attraper** une erreur avec `try/except` pour que le programme puisse continuer.
        :::

        ---

        :::tip Validation du type avec `isinstance`
        Pour une validation solide, on peut aussi vérifier que les paramètres sont du **bon type** avant même de vérifier leur valeur.

        ```python showLineNumbers
        def calculer_concentration(masse_g, volume_L):
            if not (isinstance(masse_g, int) or isinstance(masse_g, float)):
                raise TypeError("La masse doit être un nombre (int ou float).")
            if not (isinstance(volume_L, int) or isinstance(volume_L, float)):
                raise TypeError("Le volume doit être un nombre (int ou float).")
            if masse_g < 0:
                raise ValueError("La masse ne peut pas être négative.")
            if volume_L <= 0:
                raise ValueError("Le volume doit être supérieur à 0.")
            return masse_g / volume_L

        print(calculer_concentration(10, 2))     # ✅ 5.0
        print(calculer_concentration(10, "a"))   # ❌ TypeError: Le volume doit être un nombre (int ou float).
        print(calculer_concentration(-5, 2))     # Jamais atteint : le programme s'est arrêté à la ligne précédente
        ```

        La fonction `isinstance(valeur, type)` retourne `True` si la valeur est du type donné. \
        Par exemple : `isinstance(5, int)` → `True`, `isinstance("5", int)` → `False`.

        Pour accepter **plusieurs types** (ici `int` **ou** `float`), on combine deux appels avec `or`, puis on inverse le tout avec `not` : la condition est vraie seulement si la valeur n'est **ni** un `int`, **ni** un `float`.

        👉 On valide d'abord les **types**, puis les **valeurs** : une masse de type `str` ne pourrait même pas être comparée à `0` sans provoquer une erreur.
        :::

        ---

        :::note Exceptions utilisées dans ce cours
        Nous nous limitons aux trois exceptions les plus courantes :

        | Exception | Quand l'utiliser |
        |-----------|-----------------|
        | <C>TypeError</C> | Le type de la valeur n'est pas celui attendu (ex. : un texte au lieu d'un nombre) |
        | <C>ValueError</C> | La valeur est du bon type, mais ne respecte pas une contrainte (ex. : masse négative, pH hors de 0 à 14) |
        | <C>ZeroDivisionError</C> | La valeur vaut **exactement 0** et sert de **dénominateur** dans un calcul |

        👉 En cas de doute entre les deux dernières : `ZeroDivisionError` seulement pour un dénominateur nul; `ValueError` pour toutes les autres contraintes (négatif, hors intervalle, etc.). Une condition comme `volume <= 0` regroupe les deux cas : `ValueError` convient alors très bien.
        :::

        ---

        :::info 📝 Documenter les exceptions dans le docstring
        Une fonction qui peut lever des exceptions doit les **annoncer dans son docstring**, dans une section `Exceptions :`. \
        Celui qui utilise la fonction sait alors exactement quelles valeurs sont refusées, sans lire tout le code.
        ```python showLineNumbers
        def vitesse_moyenne(distance, temps):
            """
            Calcule la vitesse moyenne d'un déplacement.

            Paramètres :
            distance (float) : Distance parcourue en mètres (m)
            temps (float) : Durée du déplacement en secondes (s)

            Retourne :
            float : Vitesse moyenne en mètres par seconde (m/s)

            Exceptions :
            ValueError : si la distance ou le temps est négatif
            ZeroDivisionError : si le temps est nul
            """
            if distance < 0:
                raise ValueError("La distance ne peut pas être négative.")
            if temps == 0:
                raise ZeroDivisionError("Le temps ne peut pas être nul.")
            if temps < 0:
                raise ValueError("Le temps ne peut pas être négatif.")
            return distance / temps
        ```
        👉 C'est le format attendu dans le [TP1](/tp/tp1) : rôle, paramètres, valeur de retour **et** exceptions.
        :::

        ---

        :::warning ✅ Checklist de validation
        Avant d'écrire le calcul, votre fonction a-t-elle :
        - ✅ placé les validations **au début de la fonction, avant tout calcul**?
        - ✅ vérifié les **types** en premier (`int`, `float`, etc.), puis les **valeurs**?
        - ✅ vérifié les **domaines** (positif, non nul, dans un intervalle, etc.)?
        - ✅ couvert les **cas limites** (valeur nulle, négative, bornes de l'intervalle, etc.)?
        - ✅ donné un **message utile** à chaque `raise`, qui correspond exactement à la condition testée?
        - ✅ annoncé chaque exception dans la section `Exceptions :` du **docstring**?
        :::

    <TabItem value="affectation" label="Affectation">

        :::info Opérateurs d'affectation composés
        Nous avons déjà vu l'opérateur d'affectation `=` qui permet d'affecter une valeur à une variable :
        ```python
        x = 5
        ```

        Très souvent, on veut **modifier une variable à partir de sa propre valeur** (ajouter 1, soustraire un montant, multiplier par un facteur…). \
        Python propose des opérateurs d'affectation **composés** qui font l'opération et la réaffectation en une seule instruction.

        Les trois que vous utiliserez **le plus souvent**, notamment dans les boucles :

        | Opérateur | Exemple | Équivalent à |
        |-----------|---------|--------------|
        | <C>+=</C> | <C>a += b</C> | <C>a = a + b</C> |
        | <C>-=</C> | <C>a -= b</C> | <C>a = a - b</C> |
        | <C>*=</C> | <C>a *= b</C> | <C>a = a * b</C> |

        Les autres opérateurs composés, pour référence :

        | Opérateur | Exemple | Équivalent à |
        |-----------|---------|--------------|
        | <C>/=</C> | <C>a /= b</C> | <C>a = a / b</C> |
        | <C>//=</C> | <C>a //= b</C> | <C>a = a // b</C> |
        | <C>%=</C> | <C>a %= b</C> | <C>a = a % b</C> |
        | <C>**=</C> | <C>a **= b</C> | <C>a = a ** b</C> |
        :::

        ---

        :::tip Trois usages que vous verrez partout
        ```python showLineNumbers
        compteur = 0
        compteur += 1         # Compter : on ajoute 1 à chaque fois

        somme = 0
        somme += 25           # Accumuler : on ajoute une valeur au total

        temperature = 90
        temperature *= 0.8    # Faire évoluer une valeur : elle baisse de 20 %
        ```
        Ce sont exactement les opérations qu'on retrouvera dans les boucles de l'onglet [while](/cours/rencontre4?onglet=while) : on les répétera à chaque tour.
        :::

        ---

        :::danger Deux erreurs fréquentes
        **1. La variable doit exister avant d'être modifiée**
        ```python
        total += 5  # ❌ NameError: name 'total' is not defined
        ```
        `total += 5` veut dire `total = total + 5` : Python a besoin de l'**ancienne valeur** de `total`. \
        Il faut donc toujours **initialiser** la variable avant (`total = 0`).

        **2. Inverser les symboles : `=+` au lieu de `+=`**
        ```python
        x = 5
        x =+ 1      # ⚠️ Aucune erreur… mais x vaut maintenant 1!
        print(x)    # 1
        ```
        `x =+ 1` est lu comme `x = +1` : on affecte simplement la valeur `+1` à `x`. \
        Python n'affiche aucune erreur, ce qui rend ce bogue difficile à repérer. Le symbole de l'opération vient toujours **avant** le `=`.
        :::

    <TabItem value="while" label="while">

        :::tip 💡 L'idée clé : un `while`, c'est un `if` qui se répète
        Vous connaissez déjà le `if` : il vérifie une condition **une seule fois** et exécute son bloc si elle est vraie. \
        Le `while` fait exactement la même chose… mais **recommence** tant que la condition est vraie.

        On l'utilise quand on veut répéter une action **sans savoir d'avance combien de fois** : c'est la condition elle-même qui décide **quand s'arrêter**.

        <Row>
            <Column>
            **`if` : vérifié une seule fois**
            ```python showLineNumbers
            nombre = 3
            if nombre < 100:
                nombre *= 2
            print(nombre)  # 6
            ```
            </Column>
            <Column>
            **`while` : vérifié à chaque tour**
            ```python showLineNumbers
            nombre = 3
            while nombre < 100:
                nombre *= 2
            print(nombre)  # 192
            ```
            </Column>
        </Row>

        Combien de fois faut-il doubler `3` pour dépasser 100? On ne le sait pas d'avance (ici, 6 fois), et ça changerait si on partait d'un autre nombre. \
        Avec un `while`, pas besoin de le savoir : on double **tant que** `nombre < 100`.
        :::

        ---

        :::info Syntaxe du `while`
        En pseudo-code, la structure est la suivante :
        ```pseudo showLineNumbers
        Tant que (une certaine condition est vraie) :
            # instructions à répéter
            # instructions à répéter
            # instructions à répéter

        ```
        On répète les lignes 2 à 4 tant que la condition de la ligne 1 est vraie. \
        Dès que la condition devient fausse, on sort de la boucle et on continue à la ligne 5.

        En Python, on utilise le mot-clé `while` :
        ```python showLineNumbers
        compteur = 0
        while compteur < 5:
            print(f"Compteur = {compteur}")
            compteur += 1  # Incrémente le compteur de 1
        print("Fin de la boucle")
        ```
        À chaque ***itération*** (tour de la boucle), on affiche le compteur (ligne 3) et on l'incrémente de 1 (ligne 4). \
        Quand `compteur` atteint 5, la condition `compteur < 5` devient fausse (`False`) et la boucle se termine.

        👉 La condition est vérifiée **avant chaque tour, y compris le premier**. Si elle est fausse dès le départ (par exemple avec `compteur = 10`), le bloc n'est **jamais** exécuté, exactement comme un `if` dont la condition est fausse.

        Exécutez ce code en mode débogage : mettez un point d'arrêt sur la ligne 1 et avancez une ligne à la fois pour suivre l'évolution de `compteur`.
        :::

        :::note-nt
        Ici, on connaît d'avance le nombre de tours (5) : c'est un bon exemple pour apprendre la syntaxe. \
        À la [rencontre 5](/cours/rencontre5?onglet=for), vous verrez que la boucle `for` est plus pratique dans ce cas. Le `while`, lui, est fait pour les situations où **on ne sait pas d'avance quand s'arrêter**.
        :::

        ---

        :::warning Les 3 ingrédients d'une boucle `while`
        Toute boucle `while` a besoin de trois éléments :
        1. une **initialisation** avant la boucle : `compteur = 0`;
        2. une **condition** : `compteur < 5`;
        3. une **mise à jour** dans la boucle, qui fait évoluer la condition : `compteur += 1`.

        ⚠️ Si on oublie la mise à jour, la condition reste toujours vraie et la boucle ne s'arrête **jamais** : c'est une **boucle infinie**. \
        Quand une boucle ne se termine pas, vérifiez ces trois ingrédients!

        🛑 Si votre programme ne s'arrête plus, cliquez sur le **carré rouge ⏹ (Stop)** dans *PyCharm* (ou appuyez sur `Ctrl + F2`).
        :::

        ---

        :::info Autre exemple : une somme
        Cette boucle calcule la somme des nombres de 1 à 10 :
        ```python showLineNumbers
        somme = 0
        nombre = 1
        while nombre <= 10:
            somme += nombre  # Ajoute le nombre courant à la somme
            nombre += 1      # Passe au nombre suivant
        print(f"La somme des nombres de 1 à 10 est : {somme}")
        ```
        À chaque itération, on ajoute `nombre` à `somme`, puis on passe au nombre suivant. \
        Quand `nombre` devient 11, la condition `nombre <= 10` devient fausse et la boucle se termine.

        Exécutez-le en mode débogage pour suivre l'évolution de `somme` et de `nombre` à chaque itération!
        :::

        ---

        :::note 🧮 Les variables accumulatrices
        Dans l'exemple ci-dessus, `somme` est une **variable accumulatrice** : elle ne reçoit pas sa valeur finale d'un coup, elle **s'enrichit à chaque tour** de la boucle.

        On la reconnaît facilement :
        1. elle est **initialisée avant** la boucle (souvent à `0`);
        2. elle est **mise à jour dans** la boucle, souvent avec `+=`;
        3. on utilise sa valeur **après** la boucle.

        Un **compteur** (`compteur += 1`) est un cas particulier de variable accumulatrice : il compte le nombre de tours plutôt que d'additionner des valeurs.
        :::

        ---

        :::info 🔀 Combiner `while` et `if`
        On peut placer une structure conditionnelle **à l'intérieur** d'une boucle. \
        La condition est alors évaluée **à chaque tour** de la boucle : selon la valeur des variables à ce moment-là, le bloc `if` est exécuté ou non.

        Voici un exemple qui affiche les nombres pairs de 0 à 10 :
        ```python showLineNumbers
        i = 0
        while i <= 10:
            if i % 2 == 0:   # Condition testée à chaque tour
                print(i)
            i += 1           # Hors du if : exécuté à chaque tour
        ```
        - La boucle `while` fait varier `i` de 0 à 10.
        - À chaque tour, le `if` vérifie si `i` est pair (reste de la division par 2 égal à 0). Si oui, `i` est affiché.
        - ⚠️ L'instruction `i += 1` est indentée au niveau du `while`, **pas** du `if` : elle doit s'exécuter à chaque tour, sinon la boucle ne se terminerait jamais (dès que `i` vaut 1).
        :::

        ---

        :::tip Exemple : une tasse de café qui refroidit ☕
        Le café sort de la machine à 90 °C et sa température baisse de 20 % chaque minute. \
        **Combien de minutes faut-il attendre avant qu'il soit buvable (40 °C ou moins)?** On ne le sait pas d'avance : c'est la condition qui décide quand s'arrêter.
        ```python showLineNumbers
        temperature = 90
        minutes = 0
        while temperature > 40:
            if temperature > 60:
                print(f"Minute {minutes} : {temperature:.1f} °C, trop chaud!")
            else:
                print(f"Minute {minutes} : {temperature:.1f} °C, chaud")
            temperature *= 0.8   # La température baisse de 20 %
            minutes += 1
        print(f"Après {minutes} minutes, le café est buvable ({temperature:.1f} °C).")
        ```
        Affichage :
        ```
        Minute 0 : 90.0 °C, trop chaud!
        Minute 1 : 72.0 °C, trop chaud!
        Minute 2 : 57.6 °C, chaud
        Minute 3 : 46.1 °C, chaud
        Après 4 minutes, le café est buvable (36.9 °C).
        ```
        - Le `if`/`else` choisit le message selon la température **courante**, à chaque tour.
        - `minutes` est un compteur : il nous donne la réponse à la question une fois la boucle terminée.
        - Essayez avec une température de départ de 100 °C ou de 50 °C : le nombre de tours change, sans modifier la boucle!
        :::

                Dès qu'une exception est levée, **le programme s'arrête** : c'est voulu! Les appels suivants ne seront donc jamais exécutés. \

                À la [rencontre 5](/cours/rencontre5?onglet=try-except), vous verrez comment attraper une erreur avec `try/except` pour que le programme continue.
                :::

                Pourquoi est-il préférable d'**arrêter l'exécution avec un message clair** plutôt que de laisser Python planter avec une erreur brute?

                Définition de fonction, paramètres, `return`, validation de paramètres avec conditions, levée d'exceptions (`raise`, `ValueError`, `ZeroDivisionError`)

    <TabItem value="match" label="*match/case*">

        :::warning match/case — pour ta culture générale!
        La structure `match/case` produit des résultats très similaires à un `if/elif/else` enchaîné.
        Elle n'est **pas exigée** dans ce cours : tu ne seras **jamais évalué** dessus.\
        Si tu la trouves intuitive, libre à toi de l'utiliser. Un bon vieux `if/elif/else` fera toujours l'affaire!
        :::

        :::info match/case
        Le `match/case` est une structure de contrôle qui permet de faire des correspondances de motifs (*pattern matching*).<br />
        - Il permet de comparer une variable à plusieurs valeurs possibles.<br />
        - Il offre ainsi une alternative aux longues chaînes d'instructions `if`/`elif`/`else` pour des cas spécifiques.

        Sa syntaxe est la suivante :
        ```python showLineNumbers
        match variable:
            case valeur1:
                # code à exécuter si variable == valeur1
            case valeur2:
                # code à exécuter si variable == valeur2
            case _:
                # code à exécuter si aucune des valeurs précédentes ne correspond
        ```
        - Le `_` dans le dernier `case` agit comme un `else`, capturant tous les autres cas non spécifiés.
        - Utile pour des comparaisons simples, mais peut être moins flexible que `if`/`elif`/`else` pour des conditions complexes.
        - Exemple :
        ```python showLineNumbers
        jour = "lundi"
        match jour:
            case "lundi":
                print("Début de la semaine")
            case "mercredi":
                print("Milieu de la semaine")
            case "vendredi":
                print("Fin de la semaine")
            case _:
                print("Jour ordinaire")
        ```
        :::

        :::tip Avantages du match/case
        - Plus lisible pour des comparaisons multiples sur une même variable.
        - Permet de gérer facilement des cas spécifiques.
        - Peut être plus performant que de nombreuses instructions `if`/`elif` dans certains cas.

        👉 Il est important de noter que tout `match/case` peut être réécrit avec des `if`/`elif`/`else`, mais l'inverse n'est pas toujours vrai.
        :::
