# 🔄 Boucles et code robuste

<Tabs className="tabs-collants" queryString="onglet">

    <TabItem value="for" label="for / range" default>

        :::info Pourquoi une boucle `for`?
        À la [rencontre 4](/cours/rencontre4?onglet=while), vous avez écrit ce compteur avec un `while`. Voici le même programme avec un `for` :

        <Row>
            <Column>
            **Avec `while`**
            ```python showLineNumbers
            compteur = 0               # 1. initialisation
            while compteur < 5:        # 2. condition
                print(compteur)
                compteur += 1          # 3. mise à jour
            ```
            </Column>
            <Column>
            **Avec `for`**
            ```python showLineNumbers
            for compteur in range(5):  # 1, 2 et 3 en une seule ligne!
                print(compteur)
            ```
            </Column>
        </Row>

        Les deux affichent `0`, `1`, `2`, `3`, `4`. \
        Avec `for`, les **3 ingrédients** de la boucle `while` sont pris en charge automatiquement : impossible d'oublier la mise à jour et de créer une boucle infinie!

        👉 La boucle `for` est donc un cas particulier de `while`, plus pratique quand on **sait d'avance combien de tours** on veut faire.
        :::

        ---

        :::info Structure de la boucle `for`
        La boucle `for` parcourt une séquence de valeurs **une par une**, et exécute les instructions du bloc à chaque itération (à chaque tour de boucle) :
        ```python showLineNumbers
        for x in range(start, stop, step):
            # instructions répétées à chaque itération
        ```
        À chaque itération, `x` prend automatiquement la valeur suivante dans la séquence produite par `range()`.
        :::

        ---

        :::tip La fonction `range()`
        `range()` génère une séquence de nombres. Il existe 3 façons de l'appeler selon le nombre de paramètres :

        - `range(stop)` : part de `0`, avance de `1` en `1`, s'arrête avant `stop`
        - `range(start, stop)` : part de `start`, avance de `1` en `1`, s'arrête avant `stop`
        - `range(start, stop, step)` : part de `start`, avance de `step` en `step`, s'arrête avant `stop`

        | Appel             | Équivaut à la liste    |
        |-------------------|------------------------|
        | <C><B>range</B>(<N>5</N>)</C> | <C>[<N>0</N>, <N>1</N>, <N>2</N>, <N>3</N>, <N>4</N>]</C> |
        | <C><B>range</B>(<N>1</N>, <N>5</N>)</C> | <C>[<N>1</N>, <N>2</N>, <N>3</N>, <N>4</N>]</C> |
        | <C><B>range</B>(<N>0</N>, <N>11</N>, <N>2</N>)</C> | <C>[<N>0</N>, <N>2</N>, <N>4</N>, <N>6</N>, <N>8</N>, <N>10</N>]</C> |
        | <C><B>range</B>(<N>5</N>, <N>0</N>, -<N>1</N>)</C> | <C>[<N>5</N>, <N>4</N>, <N>3</N>, <N>2</N>, <N>1</N>]</C> |

        :::

        ---

        :::info `range()`, c'est comme une liste de nombres
        Parcourir un `range()` revient **exactement** à parcourir la liste des nombres qu'il produit. Ces deux boucles sont équivalentes :

        <Row>
            <Column>
            **Avec `range()`**
            ```python showLineNumbers
            for x in range(5):
                print(x)
            ```
            </Column>
            <Column>
            **Avec une liste écrite à la main**
            ```python showLineNumbers
            for x in [0, 1, 2, 3, 4]:
                print(x)
            ```
            </Column>
        </Row>

        Les deux affichent `0`, `1`, `2`, `3`, `4` : à chaque tour, `x` prend la valeur **suivante** de la séquence. \
        `range()` nous évite simplement d'écrire la liste nous-mêmes, ce qui serait impossible pour `range(100000)`!

        💡 Pour **voir** les nombres produits par un `range()`, convertissez-le en liste avec `list()` :
        ```python
        print(range(5))               # range(0, 5) : pas très parlant...
        print(list(range(5)))         # [0, 1, 2, 3, 4]
        print(list(range(1, 11, 2)))  # [1, 3, 5, 7, 9]
        ```
        :::

        ---

        :::danger ⚠️ La valeur `stop` n'est jamais incluse
        `range(1, 10)` produit les nombres de 1 à **9**, pas jusqu'à 10! \
        Pour inclure une valeur `n`, il faut donc s'arrêter **avant `n + 1`** :
        ```python showLineNumbers
        n = 10
        for x in range(1, n + 1):   # x vaut 1, 2, ..., 10
            print(x)
        ```
        C'est l'erreur la plus fréquente avec `range()` : en cas de doute, exécutez la boucle en mode débogage et vérifiez la **dernière** valeur de `x`.
        :::

        ---

        :::tip Exemples
        🧠 **Prédisez avant de lire!** Pour chaque exemple, cachez le commentaire de droite et écrivez sur papier la liste des valeurs que prendra `x`. \
        Vérifiez ensuite votre réponse avec `print(list(range(...)))`.

        ```python showLineNumbers
        # Exemple 1 : un seul paramètre → part de 0, s'arrête avant 5
        for x in range(5):          # comme for x in [0, 1, 2, 3, 4]
            print(x)
        ```
        ```python showLineNumbers
        # Exemple 2 : part de 1, s'arrête avant 6
        for x in range(1, 6):       # comme for x in [1, 2, 3, 4, 5]
            print(x)
        ```
        ```python showLineNumbers
        # Exemple 3 : avance de 2 en 2 → seulement les nombres pairs
        for x in range(0, 11, 2):   # comme for x in [0, 2, 4, 6, 8, 10]
            print(x)
        ```
        ```python showLineNumbers
        # Exemple 4 : step négatif → on descend, et on s'arrête avant 0
        for x in range(5, 0, -1):   # comme for x in [5, 4, 3, 2, 1]
            print(x)
        ```

        👉 Exécutez ces exemples en mode débogage, un à la fois. \
        Mettez un point d'arrêt sur le `for` et avancez ligne par ligne pour voir `x` changer de valeur à chaque itération.
        :::

        ---

        :::info Parcourir directement une liste
        On vient de voir que `for x in range(5)` revient à parcourir la liste `[0, 1, 2, 3, 4]`. \
        En fait, une boucle `for` peut parcourir **n'importe quelle liste**, directement, élément par élément :

        ```python showLineNumbers
        temperatures = [21.5, 23.0, 19.8]
        for t in temperatures:
            print(t)
        ```
        ```
        21.5
        23.0
        19.8
        ```

        À chaque tour, la variable `t` prend automatiquement la **valeur suivante** de la liste :

        Au 1er tour : `t` vaut `21.5` \
        Au 2e tour &nbsp;: `t` vaut `23.0` \
        Au 3e tour &nbsp;: `t` vaut `19.8`

        Le nom de la variable est libre : ici, `t` pour « température ».

        Ça fonctionne avec une liste de chaînes de caractères, et aussi avec un [tuple](/cours/rencontre3?onglet=tuple) :
        ```python showLineNumbers
        elements = ("Hydrogène", "Oxygène", "Carbone")
        for element in elements:
            print(f"Élément : {element}")
        ```
        ```
        Élément : Hydrogène
        Élément : Oxygène
        Élément : Carbone
        ```

        👉 Exécutez ces exemples en mode débogage : mettez un point d'arrêt sur le `for` et observez la variable de boucle changer à chaque tour.
        :::

        ---

        ::::info Quand on a besoin de la position : `range(len())`
        `for t in temperatures` donne les **valeurs**, mais pas leur **position** dans la liste. \
        Quand on a besoin de la position (pour l'afficher, pour modifier un élément, ou pour lire plusieurs listes en même temps), on parcourt plutôt les **index** avec `range(len(...))`.

        `len(liste)` retourne le nombre d'éléments d'une liste. Donc `range(len(liste))` génère exactement les bons index pour parcourir toute la liste :

        ```python showLineNumbers
        temperatures = [21.5, 23.0, 19.8]
        for i in range(len(temperatures)):          # i prendra les valeurs 0, 1, 2
            print(f"Mesure {i + 1} : {temperatures[i]}")
        ```
        ```
        Mesure 1 : 21.5
        Mesure 2 : 23.0
        Mesure 3 : 19.8
        ```

        Au 1er tour : `i` vaut `0` → `temperatures[0]` → `21.5` \
        Au 2e tour &nbsp;: `i` vaut `1` → `temperatures[1]` → `23.0` \
        Au 3e tour &nbsp;: `i` vaut `2` → `temperatures[2]` → `19.8`

        :::danger Modifier une liste : la variable de boucle ne suffit pas
        Changer `t` ne change **pas** la liste : `t` n'est qu'une **copie** de la valeur du tour.
        ```python showLineNumbers
        temperatures = [21.5, 23.0, 19.8]

        for t in temperatures:
            t = t + 1                  # ❌ modifie seulement la variable t
        print(temperatures)            # Affiche [21.5, 23.0, 19.8] : rien n'a changé!

        for i in range(len(temperatures)):
            temperatures[i] = temperatures[i] + 1   # ✅ modifie l'élément à la position i
        print(temperatures)            # Affiche [22.5, 24.0, 20.8]
        ```
        :::

        :::tip Laquelle choisir?
        - On a seulement besoin des **valeurs** → `for t in temperatures` : plus court et plus lisible.
        - On a besoin de la **position** (l'afficher, modifier la liste) → `for i in range(len(temperatures))` (ou, plus tard, la fonction [`enumerate()`](/cours/rencontre9?onglet=enumerate), vue à la rencontre 9).
        - On lit **plusieurs listes en même temps** → `range(len())` fonctionne, mais l'onglet [zip](/cours/rencontre5?onglet=zip) montre une façon plus lisible.
        :::

        👉 Exécutez ce code en mode débogage et observez `i` et `temperatures[i]` évoluer ensemble à chaque itération.
        ::::

        ---

        :::tip Quand on n'utilise pas la variable de boucle : `_`
        Parfois, on veut simplement **répéter une action** un certain nombre de fois, sans jamais utiliser la variable de boucle à l'intérieur.

        Par exemple, afficher 5 fois le même message :
        ```python showLineNumbers
        for x in range(5):
            print("Bienvenue!")  # x n'est pas utilisé
        ```

        Dans ce cas, donner un nom à la variable est trompeur : ça laisse croire qu'on va s'en servir, alors qu'on ne l'utilise pas. \
        La convention en Python est d'utiliser `_` (un tiret bas) pour signaler explicitement que la variable est intentionnellement ignorée :

        ```python showLineNumbers
        for _ in range(5):
            print("Bienvenue!")  # on répète 5 fois, la valeur du tour ne nous intéresse pas
        ```

        Le résultat est identique, mais `_` communique clairement l'intention : *"je n'ai pas besoin de savoir à quel tour je suis, je veux juste répéter."*

        👉 Règle simple pour nommer la variable de boucle :
        - c'est une **position** (un index, comme dans `temperatures[i]`) → `i`;
        - c'est une **valeur** (une température, un nombre…) → un nom parlant (`t`, `nombre`) ou `x`;
        - on ne l'utilise **jamais** → `_`.
        :::

        ---

        :::warning `for` ou `while`? Savoir choisir
        La règle est simple : **`for` quand on connaît le nombre de tours d'avance, `while` quand on ne le connaît pas**.

        On utilise un **`for`** quand le nombre d'itérations est **connu ou calculable avant** d'entrer dans la boucle :

        - *Afficher les 12 mois de l'année* → on sait qu'il y en a exactement 12.
        - *Parcourir une liste de 30 étudiants* → `len(liste)` nous donne le compte d'avance.
        - *Calculer la table de multiplication de 7 (de 1 à 10)* → exactement 10 tours.
        - *Répéter une action 5 fois* → le nombre est fixé d'avance.

        On **n'a pas le choix** d'utiliser un **`while`** quand le nombre d'itérations **dépend de quelque chose qui survient pendant l'exécution**, donc impossible à connaître d'avance :

        - *Redemander un mot de passe tant qu'il est incorrect* → l'utilisateur pourrait le réussir au 1er essai... ou au 50e. Impossible à prévoir.
        - *Générer des nombres aléatoires jusqu'à tomber sur un 6* → ça pourrait arriver tout de suite ou prendre des dizaines de tours.
        - *Continuer une partie tant que le joueur n'a pas perdu* → on ne sait pas combien de tours durera la partie.
        - *Lire des données tant qu'il en reste à lire* → le nombre dépend du contenu du fichier.

        👉 Le test mental : **« Est-ce que je peux écrire le nombre de tours sur un papier AVANT de lancer la boucle? »** Si oui → `for`. Si non → `while`.
        :::

    <TabItem value="zip" label="zip">

        :::info Le problème : parcourir deux listes en même temps
        Voici deux **listes parallèles** : le même index correspond au même élément chimique dans les deux listes.

        ```python showLineNumbers
        elements = ["Hydrogène", "Oxygène", "Carbone", "Azote"]
        masses = [1.008, 15.999, 12.011, 14.007]

        for i in range(len(elements)):
            print(f"{elements[i]} : {masses[i]} u")
        ```
        ```
        Hydrogène : 1.008 u
        Oxygène : 15.999 u
        Carbone : 12.011 u
        Azote : 14.007 u
        ```

        Ça fonctionne, mais on ne s'intéresse pas vraiment à `i` : il sert seulement à aller chercher `elements[i]` et `masses[i]`. \
        Les `[i]` partout rendent le code plus difficile à lire, surtout avec trois ou quatre listes.
        :::

        ---

        ::::info Une étape intermédiaire : parcourir une liste de tuples
        Imaginons que les mêmes données soient plutôt rangées dans **une seule liste**, où chaque élément est un [tuple](/cours/rencontre3?onglet=tuple) `(élément, masse)` :

        ```python showLineNumbers
        paires = [("Hydrogène", 1.008), ("Oxygène", 15.999), ("Carbone", 12.011), ("Azote", 14.007)]

        for paire in paires:
            print(paire)
        ```
        ```
        ('Hydrogène', 1.008)
        ('Oxygène', 15.999)
        ('Carbone', 12.011)
        ('Azote', 14.007)
        ```
        À chaque tour, la variable `paire` contient **un tuple complet**.

        On peut aussi **déballer** chaque tuple directement dans le `for`, en donnant un nom à chacune de ses valeurs :

        ```python showLineNumbers
        for element, masse in paires:
            print(f"{element} : {masse} u")
        ```
        ```
        Hydrogène : 1.008 u
        Oxygène : 15.999 u
        Carbone : 12.011 u
        Azote : 14.007 u
        ```

        :::tip-nt
        🎁 `for element, masse in paires`, c'est le concept de [déballage](/cours/rencontre3?onglet=tuple) de la rencontre 3 (`q, r = diviser(10, 3)`), répété **à chaque tour** de boucle :

        | Tour | Tuple déballé | `element` | `masse` |
        |---|---|---|---|
        | 1er | `("Hydrogène", 1.008)` | `"Hydrogène"` | `1.008` |
        | 2e | `("Oxygène", 15.999)` | `"Oxygène"` | `15.999` |
        | 3e | `("Carbone", 12.011)` | `"Carbone"` | `12.011` |
        | 4e | `("Azote", 14.007)` | `"Azote"` | `14.007` |
        :::

        ::::

        ---

        ::::info La solution : `zip()`
        On sait maintenant parcourir une liste de tuples. Mais nos données sont dans **deux listes séparées**, `elements` et `masses`… \
        C'est là qu'intervient `zip()` : elle **fabrique la liste de tuples à notre place**, en jumelant les deux listes élément par élément, comme une fermeture éclair (*zipper* en anglais) qui assemble ses deux côtés dent par dent. Chaque ligne ci-dessous montre une position :

        ```
        elements      masses     zip(elements, masses)
        "Hydrogène"   1.008   →  ("Hydrogène", 1.008)
        "Oxygène"     15.999  →  ("Oxygène", 15.999)
        "Carbone"     12.011  →  ("Carbone", 12.011)
        "Azote"       14.007  →  ("Azote", 14.007)
        ```

        Le 1er élément est jumelé avec le 1er, le 2e avec le 2e, etc. Pour le **vérifier**, on convertit le résultat en liste, comme on le fait avec `range()` :
        ```python
        print(list(zip(elements, masses)))
        # [('Hydrogène', 1.008), ('Oxygène', 15.999), ('Carbone', 12.011), ('Azote', 14.007)]
        ```
        C'est **exactement** la liste `paires` de l'étape précédente! On peut donc la parcourir de la même façon, en déballant chaque tuple :

        ```python showLineNumbers
        for element, masse in zip(elements, masses):
            print(f"{element} : {masse} u")
        ```
        ```
        Hydrogène : 1.008 u
        Oxygène : 15.999 u
        Carbone : 12.011 u
        Azote : 14.007 u
        ```

        :::tip-nt
        ✅ **Plus simple qu'avec les index :** les deux versions affichent la même chose, mais `zip()` se passe de `i` et des `[i]`, et chaque valeur a un nom parlant.

        <Row>
            <Column>
            **Avant : avec `range(len())`**
            ```python showLineNumbers
            for i in range(len(elements)):
                print(f"{elements[i]} : {masses[i]} u")
            ```
            </Column>
            <Column>
            **Après : avec `zip()`**
            ```python showLineNumbers
            for element, masse in zip(elements, masses):
                print(f"{element} : {masse} u")
            ```
            </Column>
        </Row>
        :::

        ::::

        ---

        :::info `zip()` avec trois listes (ou plus)
        `zip()` accepte autant de listes qu'on veut : il faut simplement autant de variables que de listes.

        ```python showLineNumbers
        elements = ["Hydrogène", "Oxygène", "Carbone", "Azote"]
        symboles = ["H", "O", "C", "N"]
        masses = [1.008, 15.999, 12.011, 14.007]

        for element, symbole, masse in zip(elements, symboles, masses):
            print(f"{element} ({symbole}) : {masse} u")
        ```
        ```
        Hydrogène (H) : 1.008 u
        Oxygène (O) : 15.999 u
        Carbone (C) : 12.011 u
        Azote (N) : 14.007 u
        ```
        :::

        ---

        ::::danger ⚠️ Deux pièges avec `zip()`

        **1. Des listes de longueurs différentes : aucune erreur!**

        Si les listes n'ont pas la même longueur, `zip()` s'arrête **silencieusement** à la plus courte :
        ```python showLineNumbers
        elements = ["Hydrogène", "Oxygène", "Carbone", "Azote"]
        masses = [1.008, 15.999, 12.011]          # Une masse a été oubliée!

        for element, masse in zip(elements, masses):
            print(element, masse)
        ```
        ```
        Hydrogène 1.008
        Oxygène 15.999
        Carbone 12.011
        ```
        L'azote disparaît **sans aucun message d'erreur**. Avec des données scientifiques, une valeur manquante peut ainsi passer inaperçue!

        👉 Avant d'utiliser `zip()`, assurez-vous que vos listes ont **la même longueur** (par exemple avec `len()`).

        **2. Le mauvais nombre de variables**

        Il faut **autant de variables que de listes**, comme pour tout déballage :
        ```python
        for element, symbole, masse in zip(elements, masses):   # 3 variables, mais seulement 2 listes!
        ```

        <Traceback>

        ```
        ValueError: not enough values to unpack (expected 3, got 2)
        ```

        </Traceback>

        ::::

        ---

        :::tip `zip()` ou `range(len())`?
        - On lit **plusieurs listes en même temps**, sans avoir besoin de la position → `zip()` : plus lisible, sans `[i]`.
        - On a besoin de la **position** (l'afficher, modifier une liste) → `range(len())` (ou, plus tard, la fonction [`enumerate()`](/cours/rencontre9?onglet=enumerate), vue à la rencontre 9).

        Les deux approches sont correctes : utilisez celle qui vous semble la plus claire.
        :::

        :::note 🧭 Récapitulatif : choisir sa boucle
        Vous connaissez maintenant toutes les façons de répéter des instructions vues dans cette rencontre : `while`, `for` sur un `range()`, `for` sur une liste, `range(len())` et `zip()`. \
        Pour choisir la bonne selon le problème, consultez la section [Choisir sa boucle](/aidememoire/structuresrepetitives) de l'aide-mémoire des structures répétitives, avec son arbre de décision.
        :::

    <TabItem value="forif" label="for + if">

        :::info `for` + `if`
        Un `if` placé dans une boucle `for` est évalué **à chaque tour** : selon la valeur courante, son bloc est exécuté ou non. \
        On peut ainsi **traiter chaque valeur différemment**.

        À la rencontre 4, vous avez [combiné `while` et `if`](/cours/rencontre4?onglet=while) pour afficher les nombres pairs de 0 à 10. \
        Voici le même exemple avec une boucle `for` : plus besoin d'initialiser ni d'incrémenter le compteur vous-même!
        ```python showLineNumbers
        for nombre in range(11):
            if nombre % 2 == 0:
                print(nombre)
        ```
        La boucle `for` parcourt les nombres de 0 à 10, et le `if` vérifie si le nombre est pair (reste de la division par 2 égal à 0). Si oui, le nombre est affiché.

        Exécutez ce code en mode débogage : mettez un point d'arrêt sur la ligne 1 et avancez une ligne à la fois pour suivre `nombre` et l'évaluation de la condition.
        :::

        ---

        :::tip Le `if` est-il toujours nécessaire?
        Pour les nombres pairs, on aurait pu s'en passer : `range(0, 11, 2)` les produit directement, sans `if`!

        Le `if` devient **indispensable** quand les valeurs voulues **ne suivent pas un pas régulier**. \
        Par exemple, afficher les nombres de 1 à 30 divisibles par 3 **ou** par 5 :
        ```python showLineNumbers
        for nombre in range(1, 31):
            if nombre % 3 == 0 or nombre % 5 == 0:
                print(nombre)
        ```
        Affiche (un par ligne) : 3, 5, 6, 9, 10, 12, 15, 18, 20, 21, 24, 25, 27, 30. Aucun `step` ne pourrait produire cette suite!

        👉 Règle simple : les valeurs avancent d'un **pas régulier** → utilisez le `step` de `range()`; elles dépendent d'une **condition** → utilisez un `if`.
        :::

        ---

        :::info Exemple avec une liste : compter avec une condition
        On parcourt une liste de températures : on affiche un message pour chacune et on **compte** les fièvres.
        ```python showLineNumbers
        temperatures = [36.5, 38.2, 37.1, 39.8, 36.9]
        nb_fievres = 0                              # Compteur initialisé AVANT la boucle

        for t in temperatures:
            if t > 37.5:
                print(f"{t} °C : fièvre!")
                nb_fievres += 1                     # Augmenté SEULEMENT si la condition est vraie
            else:
                print(f"{t} °C : normale")

        print(f"Nombre de fièvres : {nb_fievres}")  # Affiché APRÈS la boucle
        ```
        `nb_fievres` est une [variable accumulatrice](/cours/rencontre4?onglet=while) : un compteur qui n'augmente que lorsque la condition du `if` est vraie.

        Affichage :
        ```
        36.5 °C : normale
        38.2 °C : fièvre!
        37.1 °C : normale
        39.8 °C : fièvre!
        36.9 °C : normale
        Nombre de fièvres : 2
        ```
        👉 Exécutez ce code en mode débogage et observez comment `t` et `nb_fievres` évoluent à chaque tour.
        :::

        ---

        :::danger ⚠️ Où placer le `print` du total?
        Un `print` indenté **dans** la boucle s'exécute **à chaque tour** :
        ```python showLineNumbers
        nb_fievres = 0
        for t in temperatures:
            if t > 37.5:
                nb_fievres += 1
            print(f"Nombre de fièvres : {nb_fievres}")   # ❌ Dans la boucle : affiché 5 fois (0, 1, 1, 2, 2)
        ```
        Pour afficher le total **une seule fois**, le `print` doit être **après** la boucle, au même niveau d'indentation que le `for` :
        ```python showLineNumbers
        nb_fievres = 0
        for t in temperatures:
            if t > 37.5:
                nb_fievres += 1
        print(f"Nombre de fièvres : {nb_fievres}")       # ✅ Après la boucle : affiché une fois (2)
        ```
        :::

    <TabItem value="forfor" label="Imbrication">

        :::info Boucles imbriquées
        Il est possible de placer une boucle **à l'intérieur** d'une autre boucle : on parle alors de boucles **imbriquées**.

        💡 L'idée clé : **la boucle intérieure fait tous ses tours pour CHAQUE tour de la boucle extérieure.**
        ```python showLineNumbers
        for x in range(1, 4):          # Boucle extérieure : x vaut 1, 2, 3
            for y in range(1, 3):      # Boucle intérieure : y vaut 1, 2
                print(f"x = {x}, y = {y}")
        ```
        Affichage :
        ```
        x = 1, y = 1
        x = 1, y = 2
        x = 2, y = 1
        x = 2, y = 2
        x = 3, y = 1
        x = 3, y = 2
        ```
        - Pendant que `x` vaut 1, `y` prend **toutes** ses valeurs (1, puis 2). Ensuite seulement, `x` passe à 2… et `y` **recommence** à 1.
        - Au total, la ligne 3 est exécutée **3 × 2 = 6 fois** (3 tours extérieurs × 2 tours intérieurs).

        Exécutez ce code en mode débogage : mettez un point d'arrêt sur la ligne 1 et avancez une ligne à la fois pour voir `y` recommencer à chaque nouvelle valeur de `x`.

        On peut aussi imbriquer des boucles `while` : chaque boucle a alors besoin de ses propres [3 ingrédients](/cours/rencontre4?onglet=while) (initialisation, condition, mise à jour).
        :::

        ---

        :::tip Exemple : le plan d'une salle de spectacle 🎭
        On veut afficher tous les sièges d'une salle : 3 rangées (A, B, C) de 4 sièges chacune.
        ```python showLineNumbers
        rangees = ["A", "B", "C"]
        for rangee in rangees:                   # Boucle extérieure : chaque rangée
            for siege in range(1, 5):            # Boucle intérieure : chaque siège de la rangée
                print(f"{rangee}{siege}", end=" ")
            print()                              # Nouvelle ligne après chaque rangée
        ```
        Affichage :
        ```
        A1 A2 A3 A4
        B1 B2 B3 B4
        C1 C2 C3 C4
        ```
        - La boucle **extérieure** choisit la rangée; la boucle **intérieure** parcourt les sièges de cette rangée.
        - `end=" "` remplace le saut de ligne par une espace : les sièges d'une même rangée restent sur la même ligne (rappel : voir l'onglet [Fonctions](/cours/rencontre2?onglet=fonctions) de la rencontre 2).

        ⚠️ **L'indentation du `print()` vide est essentielle!** Il est au niveau de la boucle **extérieure** : il s'exécute une fois **après chaque rangée complète**. \
        S'il était indenté dans la boucle intérieure, il s'exécuterait après **chaque siège**, et chaque siège se retrouverait sur sa propre ligne.
        :::

        ---

        :::note Exemple : afficher un rectangle
        Voici une fonction qui prend comme paramètres une largeur et une hauteur, et qui affiche un rectangle de `#` de ces dimensions :
        ```python showLineNumbers
        def afficher_rectangle(largeur, hauteur):
            for _ in range(hauteur):          # Boucle pour chaque ligne
                for _ in range(largeur):      # Boucle pour chaque colonne
                    print('#', end='')        # Affiche un '#' sans saut de ligne
                print()                       # Nouvelle ligne après chaque ligne de '#'

        afficher_rectangle(5, 3)
        ```
        Il devrait afficher :
        ```
        #####
        #####
        #####
        ```
        Les valeurs des variables de boucle ne sont jamais utilisées : on les nomme donc `_` (voir l'onglet [for / range](/cours/rencontre5?onglet=for)).

        Voici maintenant une version qui utilise la concaténation de chaînes de caractères (`str`) pour construire chaque ligne avant de l'afficher :
        ```python showLineNumbers
        def afficher_rectangle(largeur, hauteur):
            for _ in range(hauteur):          # Boucle pour chaque ligne
                ligne = ''                    # Initialise une chaîne vide pour la ligne
                for _ in range(largeur):      # Boucle pour chaque colonne
                    ligne += '#'              # Concatène un '#' à la chaîne de la ligne
                print(ligne)                  # Affiche la ligne complète

        afficher_rectangle(5, 3)
        ```
        Le résultat est le même, mais la méthode est différente : on évite d'appeler `print()` à chaque itération de la boucle intérieure. \
        Exécutez ce code en mode débogage pour voir la chaîne `ligne` s'allonger à chaque itération de la boucle intérieure.
        :::

    <TabItem value="break" label="break / continue">

        :::info Instructions `break` et `continue`
        Parfois, on veut **interrompre** une boucle avant qu'elle se termine naturellement, ou **sauter** certaines itérations. \
        Python fournit deux instructions spéciales pour ces situations : `break` et `continue`.
        :::

        ---

        :::info `break` : sortir de la boucle
        `break` fait sortir **immédiatement** de la boucle (`for` ou `while`). L'exécution continue à la première ligne **après** la boucle.

        Il est très utile pour une **recherche** : dès qu'on a trouvé ce qu'on cherche, inutile de continuer à parcourir la liste!
        ```python showLineNumbers
        temperatures = [36.5, 37.1, 38.2, 36.9, 39.8]
        for i in range(len(temperatures)):
            print(f"Vérification de {temperatures[i]} °C")
            if temperatures[i] > 37.5:
                print(f"Première fièvre trouvée à la position {i}!")
                break                   # On a trouvé : on arrête de chercher
        print("Fin de la recherche")
        ```
        Affichage :
        ```
        Vérification de 36.5 °C
        Vérification de 37.1 °C
        Vérification de 38.2 °C
        Première fièvre trouvée à la position 2!
        Fin de la recherche
        ```
        👉 Les températures 36.9 et 39.8 ne sont **jamais vérifiées** : le `break` a terminé la boucle à la position 2.
        :::

        ---

        :::info `continue` : passer au tour suivant
        `continue` saute **tout le reste du tour** en cours et passe directement à l'itération suivante.

        Il est utile pour **ignorer des valeurs invalides**. Ici, un capteur enregistre `-999` lorsqu'une mesure a échoué :
        ```python showLineNumbers
        mesures = [21.5, -999, 23.0, 19.8, -999]
        somme = 0
        nb_valides = 0
        for m in mesures:
            if m == -999:
                continue                # Mesure invalide : on passe directement à la suivante
            print(f"Mesure valide : {m}")
            somme += m
            nb_valides += 1
        print(f"Moyenne : {somme / nb_valides:.1f}")
        ```
        Affichage :
        ```
        Mesure valide : 21.5
        Mesure valide : 23.0
        Mesure valide : 19.8
        Moyenne : 21.4
        ```
        👉 Pour chaque `-999`, les lignes 7 à 9 sont **toutes** sautées : la mesure n'est ni affichée, ni additionnée, ni comptée.
        :::

        ---

        :::warning ⚠️ Avec des boucles imbriquées
        `break` et `continue` n'agissent que sur la boucle **la plus proche** (celle dans laquelle ils se trouvent directement) :
        ```python showLineNumbers
        for x in range(1, 4):
            for y in range(1, 4):
                if y == 2:
                    break               # Sort SEULEMENT de la boucle sur y
                print(f"x = {x}, y = {y}")
        ```
        Affichage :
        ```
        x = 1, y = 1
        x = 2, y = 1
        x = 3, y = 1
        ```
        👉 Le `break` arrête la boucle intérieure, mais la boucle extérieure **continue** : `x` passe quand même à 2, puis à 3.
        :::

        ---

        :::tip Avec modération!
        `break` et `continue` sont pratiques, mais ils rendent le chemin d'exécution plus difficile à suivre. \
        Si une condition claire dans le `while` ou un simple `if` suffit, c'est souvent plus lisible. Réservez-les aux cas où ils **simplifient vraiment** le code : une recherche à arrêter dès qu'on a trouvé, des valeurs à ignorer, etc.

        Exécutez les exemples de cet onglet en mode débogage : avancez ligne par ligne et observez exactement où l'exécution saute après un `break` ou un `continue`.
        :::

    <TabItem value="input" label="input()">

        :::info La fonction `input()`
        La fonction `input()` permet de demander à l'utilisateur de **saisir** une valeur au clavier. \
        Elle peut être utilisée avec ou sans paramètre :
        - sans paramètre, elle attend simplement une saisie;
        - avec un paramètre, elle affiche d'abord un message pour guider l'utilisateur.

        Essayez ce code dans un script Python :
        ```python showLineNumbers
        # Sans paramètre
        saisie_utilisateur = input()   # Attend une saisie de l'utilisateur
        print(saisie_utilisateur)

        # Avec un paramètre
        prenom = input("Veuillez saisir votre prénom : ")
        print(prenom)
        ```
        💡 Terminez toujours le message par une **espace** (`"... prénom : "`) : sinon, ce que l'utilisateur tape se colle directement au texte.
        :::

        ---

        :::warning La fonction `input()` met le programme sur pause!
        Lorsque `input(...)` est exécutée, le programme **attend** que l'utilisateur écrive quelque chose et appuie sur la touche **Entrée**. \
        C'est donc **normal** que l'instruction suivante ne soit pas exécutée tant que vous n'avez rien saisi!

        Dans *PyCharm* :
        - **cliquez dans la console** (fenêtre *Run*) avant de taper votre réponse, puis appuyez sur **Entrée**;
        - en mode débogage, la réponse se tape dans la console de la fenêtre *Debug*. Le programme semble « figé » tant que vous n'avez pas répondu : il ne plante pas, il vous attend!
        :::

        ---

        :::info `input()` retourne toujours du texte
        La fonction `input(...)` retourne **TOUJOURS** une chaîne de caractères (`str`), même si l'utilisateur saisit un nombre. \
        Pour utiliser la valeur dans un calcul, il faut la convertir avec `int()` ou `float()` :
        ```python showLineNumbers
        # Demander un nombre entier (int)
        age = int(input("Entrez votre âge : "))
        print(f"Dans 10 ans, vous aurez {age + 10} ans.")

        # Demander un nombre décimal (float)
        taille = float(input("Entrez votre taille en mètres : "))
        print(f"Votre taille en centimètres est {taille * 100} cm.")
        ```
        `int()` convertit la chaîne en nombre entier et `float()` en nombre décimal.
        :::

        ---

        :::danger ⚠️ Ce qui arrive si on oublie la conversion
        Sans `int()` ou `float()`, Python traite la saisie comme du **texte** :
        ```python showLineNumbers
        age = input("Entrez votre âge : ")    # L'utilisateur tape 17
        print(age + 10)                       # ❌ TypeError: can only concatenate str (not "int") to str
        ```
        ```python showLineNumbers
        a = input("Premier nombre : ")        # L'utilisateur tape 5
        b = input("Deuxième nombre : ")       # L'utilisateur tape 3
        print(a + b)                          # 53  (les deux textes sont collés, ce n'est pas une addition!)
        print(a * 3)                          # 555 (le texte est répété 3 fois!)
        ```
        👉 Si vous obtenez un `TypeError` avec `str`, ou un résultat « collé » comme `53`, vérifiez d'abord que vous avez bien converti la saisie.
        :::

        ---

        :::warning Attention à la virgule décimale!
        En français, on écrit souvent `1,75`. Mais Python utilise le **point** comme séparateur décimal :
        ```python
        float("1.75")   # ✅ 1.75
        float("1,75")   # ❌ ValueError: could not convert string to float: '1,75'
        ```
        Quand votre programme demande un nombre décimal, tapez-le avec un **point** (`1.75`).
        :::

        ---

        :::tip `input()` dans une boucle
        On peut placer un `input()` dans une boucle `while` pour **redemander** tant que la réponse ne convient pas :
        ```python showLineNumbers
        reponse = ""
        while reponse != "oui":
            reponse = input("Avez-vous terminé? (oui/non) : ")
        print("Bravo!")
        ```
        - `reponse` est initialisée à une chaîne vide avant la boucle, pour que la condition soit vraie au premier tour.
        - Tant que l'utilisateur ne tape pas exactement `oui`, la question est reposée.
        :::

    <TabItem value="try-except" label="try/except">

        :::info Rappel : `raise` met une barrière dans une fonction
        À la [rencontre 4](/cours/rencontre4?onglet=exceptions-validation), vous avez protégé la fonction `vitesse_moyenne` avec `raise` :
        ```python showLineNumbers
        def vitesse_moyenne(distance, temps):
            if distance < 0:
                raise ValueError("La distance ne peut pas être négative.")
            if temps == 0:
                raise ZeroDivisionError("Le temps ne peut pas être nul.")
            if temps < 0:
                raise ValueError("Le temps ne peut pas être négatif.")
            return distance / temps
        ```
        Le problème : dès qu'une erreur est levée, **tout le programme s'arrête**. \
        Avec `try/except`, c'est maintenant **l'appelant** qui peut décider quoi faire en cas d'erreur.
        :::

        ---

        :::tip `try/except` — mettre un filet de sécurité à l'appel
        `try/except` permet de **rattraper** une erreur qui se produit, plutôt que de laisser le programme planter.

        Exécutez ce code sans `try/except`, observez l'erreur, puis ajoutez le filet et relancez :
        ```python showLineNumbers
        # Sans filet : le programme plante
        print(vitesse_moyenne(100, 20))    # ✅ 5.0
        print(vitesse_moyenne(-50, 10))    # ❌ Le programme s'arrête ici avec une erreur
        print(vitesse_moyenne(100, 0))     # Jamais atteint
        ```

        ```python showLineNumbers
        # Avec filet : le programme gère l'erreur proprement
        try:
            print(vitesse_moyenne(100, 20))    # ✅ Exécuté normalement
            print(vitesse_moyenne(-50, 10))    # ❌ Lève ValueError → on saute au except
            print(vitesse_moyenne(100, 0))     # ⏭️ Jamais atteint (on est déjà dans le except)
        except ValueError as e:
            print(f"Une erreur est survenue : {e}")
        print("Suite du programme")            # ✅ Le programme continue!
        ```
        Affichage :
        ```
        5.0
        Une erreur est survenue : La distance ne peut pas être négative.
        Suite du programme
        ```
        - Dès qu'une erreur survient dans le `try`, le **reste du `try` est sauté** et Python exécute le bloc `except`.
        - Après le `except`, le programme **continue normalement** : il ne plante plus!
        - La variable `e` contient le message d'erreur passé à `raise`. On peut l'afficher, l'enregistrer dans un fichier, ou réagir différemment selon l'erreur.
        :::

        ---

        :::info Plusieurs `except` pour plusieurs types d'erreurs
        `vitesse_moyenne` peut lever deux types d'exceptions : `ValueError` (distance ou temps négatif) et `ZeroDivisionError` (temps nul). \
        On peut écrire un bloc `except` **pour chaque type**, et réagir différemment :
        ```python showLineNumbers
        try:
            print(vitesse_moyenne(100, 0))
        except ValueError as e:
            print(f"Valeur invalide : {e}")
        except ZeroDivisionError as e:
            print(f"Division impossible : {e}")
        ```
        Affichage :
        ```
        Division impossible : Le temps ne peut pas être nul.
        ```
        Python vérifie les blocs `except` **dans l'ordre** et exécute **seulement le premier** qui correspond au type de l'erreur.
        :::

        ---

        :::tip Exemple avec `input()` : l'utilisateur ne tape pas un nombre 🙃
        Une saisie utilisateur est **imprévisible**. Si l'utilisateur tape « abc », `int()` lève une `ValueError` et le programme plante. \
        Avec une boucle `while` et un `try/except`, on peut redemander jusqu'à obtenir une réponse valide :

        ```python showLineNumbers
        valide = False
        while not valide:
            try:
                age = int(input("Quel âge as-tu? "))
                valide = True   # Atteint seulement si la conversion a réussi
            except ValueError:
                print("Ce n'est pas un nombre entier, réessayez!")
        print(f"Dans 10 ans, tu auras {age + 10} ans.")
        ```
        Si `int()` lève une erreur, Python saute directement au `except` : la ligne `valide = True` n'est pas exécutée et la boucle recommence. \
        Dès qu'une saisie est valide, `valide` devient `True` et la boucle se termine.
        :::

        ---

        :::note Différence fondamentale entre `raise` et `try/except`

        | Mécanisme | Rôle | Où l'écrire |
        |-----------|------|-------------|
        | <C><K>raise</K></C> | **Signaler** un problème (mettre une barrière) | **Dans** la fonction, là où les paramètres sont vérifiés |
        | <C><K>try</K>/<K>except</K></C> | **Attraper** un problème (mettre un filet) | **À l'appel** de la fonction, pour gérer proprement les erreurs et éviter l'arrêt du programme |

        👉 On utilise `raise` pour protéger la fonction, et `try/except` pour que l'appelant décide quoi faire en cas d'erreur.
        :::

        ---

        ::::info Les fonctions de Python lèvent aussi des exceptions!
        Ce n'est pas seulement votre code qui peut lever des exceptions — les fonctions de la **bibliothèque standard** de Python le font aussi.\
        Comprendre quelles erreurs elles peuvent produire vous aide à les anticiper et même les intercepter (avec un bloc `try/except`) pour éviter l'arrêt pur et simple du programme.

        **`math` — erreurs de domaine mathématique**

        ```python showLineNumbers
        import math

        math.sqrt(25)     # ✅ 5.0
        math.sqrt(-1)     # ❌ ValueError: math domain error  (racine d'un nombre négatif)

        math.log(100)     # ✅ 4.605...
        math.log(0)       # ❌ ValueError: math domain error  (log(0) est indéfini)
        math.log(-5)      # ❌ ValueError: math domain error  (log d'un négatif)

        math.factorial(5) # ✅ 120
        math.factorial(-1)# ❌ ValueError: factorial() not defined for negative values
        math.factorial(2.5)# ❌ TypeError: 'float' object cannot be interpreted as an integer
        ```

        👉 Le module `math` lève une `ValueError` dès qu'on sort du **domaine mathématique valide** (valeur impossible à calculer).

        ---

        **`int()` et `float()` — erreurs de conversion**

        ```python showLineNumbers
        int("42")         # ✅ 42
        int("3.14")       # ❌ ValueError: invalid literal for int() with base 10: '3.14'
        int("abc")        # ❌ ValueError: invalid literal for int() with base 10: 'abc'

        float("3.14")     # ✅ 3.14
        float("abc")      # ❌ ValueError: could not convert string to float: 'abc'
        ```

        👉 `int()` et `float()` lèvent une `ValueError` si la chaîne de caractères **ne représente pas un nombre valide**.\
        C'est une erreur très fréquente quand on lit une saisie utilisateur ou des données provenant d'un fichier.

        ---

        **Intercepter ces erreurs avec `try/except`**

        Voici un exemple concret qui combine `math` et la conversion :

        ```python showLineNumbers
        import math

        def calculer_racine(valeur_texte):
            try:
                nombre = float(valeur_texte)        # Peut lever ValueError si non numérique
                resultat = math.sqrt(nombre)        # Peut lever ValueError si nombre < 0
                return resultat
            except ValueError as e:
                print(f"Erreur : {e}")
                return None

        #Toutes les instructions ci-dessous sont exécutées!
        print(calculer_racine("25"))   # ✅ 5.0
        print(calculer_racine("-4"))   # ✅ La fonction gère l'erreur pour éviter l'arrêt du programme et elle retourne None
        print(calculer_racine("abc"))  # ✅ La fonction gère l'erreur pour éviter l'arrêt du programme et elle retourne None
        a = 1 + 2                      # Cette instruction est finalement exécutée!
        ```

        👉 Un seul bloc `try/except` attrape à la fois les erreurs de conversion **et** les erreurs de domaine, car les deux lèvent une `ValueError`.
        L'appel de la fonction `calculer_racine()` ne causera **jamais l'arrêt du programme** car les erreurs sont bien attrapées.
        La fonction retourne donc :
            - une valeur valide si tout s'est bien passé;
            - la valeur `None` si une erreur a été attrapée.

        ---

        **Bonne pratique : lire la documentation avant d'utiliser une fonction**

        Les exemples ci-dessus ne sont pas une liste exhaustive — chaque fonction de Python peut avoir son propre comportement en cas d'erreur.\
        Avant d'utiliser une fonction inconnue, **consultez sa documentation** pour savoir quelles exceptions elle peut lever et dans quelles circonstances.

        Par exemple, la page de documentation de [`math.sqrt`](https://docs.python.org/3/library/math.html) indique explicitement qu'une `ValueError` est levée si l'argument est négatif. C'est cette information qui vous permet d'écrire un `try/except` adapté — ni trop large (attraper des erreurs imprévues), ni trop étroit (manquer un cas réel).
        ::::

        ---

        :::danger ⚠️ Toujours préciser le type d'erreur après `except`
        Python permet d'écrire `except` **seul**, sans type d'erreur : il attrape alors **toutes** les erreurs… y compris vos propres bogues!
        ```python showLineNumbers
        try:
            age = int(imput("Quel âge as-tu? "))   # Faute de frappe : imput au lieu de input
        except:
            print("Ce n'est pas un nombre entier!")
        ```
        Ce programme affiche **toujours** « Ce n'est pas un nombre entier! », même avant que l'utilisateur ait tapé quoi que ce soit. \
        La vraie erreur (`NameError: name 'imput' is not defined`) est **cachée** : impossible de comprendre ce qui ne va pas!

        Avec `except ValueError:`, seules les erreurs de conversion sont attrapées. La `NameError` s'affiche normalement, avec un message qui pointe directement vers la faute de frappe.
        :::

        ---

        :::warning ✅ Checklist : bien utiliser `try/except`
        - 🤔 Quand vous intégrez une nouvelle fonction, demandez-vous : **« Qu'est-ce qui pourrait mal se passer ici, et est-ce que mon code le gère? »**
        - 🎯 Précisez toujours le **type d'erreur** attendu après `except` (ex. : `except ValueError`), jamais un `except` seul.
        - 📖 Consultez la **documentation** d'une fonction inconnue pour savoir quelles exceptions elle peut lever.
        :::

    <TabItem value="DRY" label="DRY">

        :::info DRY : *Don't Repeat Yourself*
        En programmation, on suit le principe **DRY** (*Don't Repeat Yourself*, « ne vous répétez pas »). \
        Du code répété est plus long à lire, et surtout plus difficile à modifier : une correction doit être faite à **chaque** endroit où le code a été copié, et il est facile d'en oublier un.

        Vous connaissez maintenant **trois outils** pour éviter la répétition :
        | Situation | Outil |
        |-----------|-------|
        | On répète le même **calcul ou traitement** à plusieurs endroits du programme | Une **fonction** (voir l'onglet [DRY de la rencontre 3](/cours/rencontre3?onglet=DRY)) |
        | La même instruction se retrouve dans **tous les blocs** d'un `if/elif/else` | **Sortir l'instruction** du bloc conditionnel (section 1 ci-dessous) |
        | On copie-colle un bloc en changeant seulement quelques valeurs | Une **boucle** (section 2 ci-dessous) |
        :::

        ---

        ## 1️⃣ Dans les structures conditionnelles

        :::info Une instruction présente dans tous les blocs n'est pas conditionnelle!
        Si une instruction se retrouve à la fois dans le `if` **et** dans le `else`, elle s'exécutera dans **tous les cas** de toute façon. \
        Elle devrait donc être placée **en dehors** du bloc conditionnel : soit **avant**, soit **après**, selon sa position dans les blocs.
        :::

        ---

        :::danger ⚠️ Avant le bloc — exemple avec une instruction redondante au début
        Repérez l'instruction répétée inutilement dans les deux blocs :
        ```python showLineNumbers
        # Version redondante
        temperature = 37.8

        if temperature > 37.5:
            print("Initialisation du protocole de mesure...")  # ❌ Répété au début des 2 blocs!
            print("⚠️ Fièvre détectée : consulter un médecin.")
        else:
            print("Initialisation du protocole de mesure...")  # ❌ Répété au début des 2 blocs!
            print("✅ Température normale.")
        ```
        Peu importe la valeur de `temperature`, l'initialisation du protocole est **toujours** affichée.\
        La répéter dans les deux blocs est inutile et rend le code plus difficile à maintenir.
        :::

        ---

        :::tip ✅ La bonne approche : sortir l'instruction commune avant le bloc
        ```python showLineNumbers
        # Version sans redondance
        temperature = 37.8

        print("Initialisation du protocole de mesure...")  # ✅ Exécuté dans tous les cas avant les 2 blocs

        if temperature > 37.5:
            print("⚠️ Fièvre détectée : consulter un médecin.")
        else:
            print("✅ Température normale.")
        ```
        Le code est plus court, plus lisible, et plus facile à modifier : si le message d'initialisation change, on n'a qu'**un seul endroit** à modifier.
        :::

        ---

        :::danger ⚠️ Après le bloc — exemple avec une instruction redondante à la fin
        Même problème, mais cette fois l'instruction répétée se trouve à la **fin** de chaque bloc :
        ```python showLineNumbers
        # Version redondante
        masse_g = 5.2
        volume_mL = 10.0

        if masse_g > 0 and volume_mL > 0:
            densite = masse_g / volume_mL
            print(f"Densité calculée : {densite} g/mL")
            print("--- Fin de l'analyse ---")  # ❌ Répété à la fin des 2 blocs!
        else:
            print("⚠️ Paramètres invalides, calcul impossible.")
            print("--- Fin de l'analyse ---")  # ❌ Répété à la fin des 2 blocs!
        ```
        :::

        ---

        :::tip ✅ La bonne approche : sortir l'instruction commune après le bloc
        ```python showLineNumbers
        # Version sans redondance
        masse_g = 5.2
        volume_mL = 10.0

        if masse_g > 0 and volume_mL > 0:
            densite = masse_g / volume_mL
            print(f"Densité calculée : {densite} g/mL")
        else:
            print("⚠️ Paramètres invalides, calcul impossible.")

        print("--- Fin de l'analyse ---")  # ✅ Exécuté dans tous les cas après les 2 blocs
        ```
        :::

        ---

        :::note 🧠 Récapitulatif — où placer les instructions communes?

        | Position de la redondance | Solution |
        |---------------------------|----------|
        | Au **début** de chaque bloc | Placer l'instruction **avant** le bloc `if` |
        | À la **fin** de chaque bloc | Placer l'instruction **après** le bloc `if/else` |
        | Au **début et à la fin** | Placer une instruction **avant** et une **après** |

        👉 La règle est simple : si une instruction s'exécute **dans tous les cas**, elle ne devrait **jamais** se retrouver à l'intérieur d'un `if` ou d'un `else`.

        ⚠️ On ne peut sortir une instruction que si elle se trouve dans **chacun** des blocs : le `if`, **chaque** `elif` et le `else`. \
        S'il manque dans un seul bloc, elle ne s'exécute pas dans tous les cas : elle doit donc rester à l'intérieur.
        :::

        ---

        :::warning Attention — ne pas confondre redondance et répétition intentionnelle!
        Parfois, deux instructions se ressemblent mais **ne sont pas identiques** : elles ne peuvent donc pas être sorties du bloc.
        ```python showLineNumbers
        # ✅ Ce n'est PAS de la redondance, car les messages sont différents!
        ph = 4.2

        if ph < 7:
            print(f"Le pH de {ph} indique une solution acide.")
        else:
            print(f"Le pH de {ph} indique une solution basique ou neutre.")
        ```
        Ici, les deux `print` contiennent du texte différent. Ils doivent rester dans leurs blocs respectifs.
        :::

        ---

        ## 2️⃣ Avec des boucles

        :::info Un bloc copié-collé? Une boucle!
        Si vous copiez-collez un bloc d'instructions en changeant seulement quelques valeurs, c'est le signe qu'il faut utiliser une **boucle**.
        :::

        ---

        :::danger ⚠️ Le code redondant
        Voici un programme qui affiche les informations de trois étudiants. Le bloc d'instructions est répété trois fois, seules les valeurs changent :
        ```python showLineNumbers
        print("Étudiant #1")
        print("Nom : Félix")
        print("Note : 72")
        print()

        print("Étudiant #2")
        print("Nom : Dayron")
        print("Note : 91")
        print()

        print("Étudiant #3")
        print("Nom : Léa")
        print("Note : 58")
        print()
        ```
        Ce code fonctionne, mais il est difficile à maintenir : ajouter un 4e étudiant oblige à copier-coller un nouveau bloc. Et si le format d'affichage change, il faut modifier trois endroits!
        :::

        ---

        :::note Étape 1 : Identifier ce qui change
        En observant les trois blocs, on remarque que seules trois choses varient d'un bloc à l'autre :
        - Le **numéro** de l'étudiant (`#1`, `#2`, `#3`)
        - Le **nom** (`Félix`, `Dayron`, `Léa`)
        - La **note** (`72`, `91`, `58`)

        Le numéro correspond simplement à la position dans la liste (index `0`, `1`, `2`), donc on peut le calculer automatiquement avec `i + 1`.<br />
        On regroupe les noms et les notes dans des **listes parallèles** :
        ```python showLineNumbers
        noms  = ["Félix", "Dayron", "Léa"]
        notes = [72, 91, 58]
        ```
        :::

        ---

        :::tip ✅ Étape 2 : Remplacer la répétition par une boucle
        Maintenant qu'on a les données dans des listes, une seule boucle suffit pour traiter tous les étudiants :
        ```python showLineNumbers
        noms  = ["Félix", "Dayron", "Léa"]
        notes = [72, 91, 58]

        nb_elements = len(noms)
        for i in range(nb_elements):
            print(f"Étudiant #{i + 1}")
            print(f"Nom : {noms[i]}")
            print(f"Note : {notes[i]}")
            print()
        ```
        Le résultat affiché est **identique** à la version redondante, mais le code est bien plus court et plus facile à maintenir.

        💡 Ici, on garde `range(len())` parce qu'on a besoin de la **position** pour le numéro (`i + 1`). À la [rencontre 9](/cours/rencontre9?onglet=enumerate), `enumerate()` permettra d'écrire la même boucle sans `[i]`.
        :::

        ---

        :::info L'avantage clé : la flexibilité
        Pour ajouter un 4e étudiant, on n'ajoute qu'**un élément dans chaque liste** et la boucle s'adapte automatiquement grâce à `len()` :
        ```python showLineNumbers
        noms  = ["Félix", "Dayron", "Léa", "Tristan"]
        notes = [72, 91, 58, 83]

        nb_elements = len(noms)
        for i in range(nb_elements):
            print(f"Étudiant #{i + 1}")
            print(f"Nom : {noms[i]}")
            print(f"Note : {notes[i]}")
            print()
        ```
        👉 Le corps de la boucle n'a pas changé d'une seule ligne. C'est la puissance de combiner les listes et les boucles!
        :::

        ---

        :::tip 🧭 Méthode : remplacer une répétition par une boucle
        1. **Repérer** le bloc d'instructions qui se répète.
        2. **Identifier ce qui change** d'une répétition à l'autre (les valeurs, le numéro, le nombre d'éléments…).
        3. Mettre ces valeurs dans une **liste**, ou les **calculer** à partir de `i` (comme `i + 1` pour le numéro).
        4. Écrire la **boucle**, avec le bloc commun à l'intérieur.

        Vérifiez ensuite que le résultat affiché est **identique** à celui de la version répétitive.
        :::
