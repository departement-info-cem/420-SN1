## Explications

:::tip Le lien avec le débogage pas à pas
La colonne `#ligne` correspond exactement aux numéros de lignes que vous voyez défiler dans votre éditeur lorsque vous exécutez votre programme en mode débogage (pas à pas). Chaque ligne de la trace représente un moment précis de l'exécution, tout comme chaque fois que vous appuyez sur **Pas suivant** (Step Over / Step Into) dans le débogueur.

Produire une trace à la main, c'est donc faire le travail du débogueur dans votre tête.
:::

---

:::info Portée des variables
On indique la portée des variables en les regroupant par portée (première ligne).<br/>
Ici, on a la portée globale (variables définies en dehors de toute fonction), la portée de `affiche_resultat()` et la portée de `carre()`.<br/>

On remarque que la variable `n` n'existe que dans la portée de la fonction `carre()`, et que les variables `a`, `b` et `total` n'existent que dans la portée de la fonction `affiche_resultat()`.<br/>

La variable `z` est dans la portée globale, c'est pourquoi elle est visible dans toute la trace.

:::

---

:::info Contexte
La colonne **contexte** indique **où se trouve l'exécution** au moment de chaque ligne :
- `globale` lorsque la ligne exécutée est à l'extérieur de toute fonction (le programme principal);
- **le nom de la fonction en cours d'exécution** lorsque la ligne exécutée est à l'intérieur d'une fonction.

Dans l'exemple ci-dessus :
- À la ligne 11, l'appel `affiche_resultat()` se fait depuis le programme principal : le contexte est encore `globale`.
- Aux lignes 5 à 8, on exécute le code de `affiche_resultat` : le contexte est `affiche_resultat`.
- À la ligne 7, `carre(a)` est appelée : la ligne suivante (ligne 2) s'exécute dans le contexte `carre`.
- Une fois le `return` exécuté, on revient à la ligne 7, de nouveau dans le contexte `affiche_resultat`.

👉 Le contexte indique quelles variables sont accessibles : seules celles de la portée globale et de la portée du contexte courant ont une valeur sur cette ligne de la trace.
:::

---

Voici maintenant un petit exemple qui démontre l'importance de spécifier la portée des variables, où on a une variable `x` dans la portée globale et une autre variable nommée `x` dans la portée de la fonction `ma_fonction()`.

### Code
```python showLineNumbers
def ma_fonction(y):
    x = 3 + y
    print(f'dans ma_fonction, x vaut {x}')

x = 5
print(f'dans main, x vaut {x}')
ma_fonction(100)
print(f'dans main, x vaut toujours {x}')
```

:::warning Portée des variables
- On voit que la variable `x` dans la portée de `ma_fonction()` n'a rien à voir avec la variable `x` dans la portée globale.
- Cette dernière n'est pas modifiée par l'exécution de `ma_fonction()`, malgré le fait qu'on ait une instruction `x = 3 + y` dans `ma_fonction()` et que la variable globale `x` soit aussi accessible dans `ma_fonction()` (car elle est globale).
- La raison est que l'instruction `x = 3 + y` crée une nouvelle variable ***locale*** `x` dans la portée de `ma_fonction()`, qui masque la variable ***globale*** `x`.
- Si on voulait modifier la variable globale `x` dans `ma_fonction()`, il faudrait utiliser le mot-clé `global` (ce qui est déconseillé en général).
:::
